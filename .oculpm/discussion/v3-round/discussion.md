## 문제 정의

3.0.0 을 낸다. 요청된 방향은 넷이었다 — **더 사용자 친화적이고 미학적·공학적으로 설계된 UI**,
**더 나은 UX**, **현재 ocul-pm 의 문제점과 개선 가능한 점**, 그리고 **`block/buzz` 에서 가져올
기술**.

결정할 것은 하나다: **3.0 은 무엇인가.** 시각 라운드인가, 기구(mechanism) 라운드인가, 부채
청산 라운드인가, 아니면 그 셋을 한 태그에 묶는 것인가. 그리고 그 안에서 **무엇을 먼저 하는가.**

이 문서는 그 결정을 위한 회의록이다. 실행 계획이 아니다 — 결정이 서면 플래너로 승격한다.

배경 압력 셋:

1. 플랜 41개 중 40개가 `done`, 활성은 `sessions-screen` 하나뿐이다. **작업이 없는 게 아니라
   라운드 사이에 서 있다.** 큰 방향을 정하기 가장 싼 시점이다.
2. 5주에 Rust +49%, 파일 +46% 로 자랐다(v2.23.0 → v2.40.0). 성장의 부산물이 특정 자리에
   몰려 있고, 그 자리를 지나지 않고 3.0 을 짓기 어렵다.
3. `[buzz-borrows]` 가 어제 `resolved` 로 닫혔는데, **그 라운드가 buzz 의 절반을 오독했다**
   (아래 E-0). 그래서 기각·보류 판정 일부가 3.0 렌즈에서 뒤집힌다.

## 조사 방법과 한계

**opus5 병렬 세션 다섯**을 서로 겹치지 않는 범위로 띄웠다. 각 세션에 공통 제약을 걸었다 —
소스·`.oculpm/`·git 상태 무변경, **앱 실행 금지**(사용자 설치본과 번들 id 를 공유해 app-data·
SQLite·`.oculpm` 락이 경합한다, `[no-dev-build-while-app-runs]`), 빌드·테스트 실행 금지,
추측을 사실로 쓰지 말 것, **과거 도그푸딩 기록을 먼저 읽어 이미 고쳐진 것을 새 결함으로
보고하지 말 것**.

| 세션 | 범위 | 규모 |
|---|---|---|
| A 제품 결함 | README·랜딩 주장 vs 실제 코드, 미완 표면, 삼켜지는 실패, done 플랜의 이월 백로그 | 107 도구호출 |
| B UI 비주얼 | CSS 21파일 14,707줄, 화면 17개 골격, 토큰·프리셋·타이포·대비 | 57 |
| C UX·정보구조 | 첫 실행→매일→장기 여정, IA 재편, 되돌리기·접근성·설정 | 124 |
| D 아키텍처 | 모듈 경계·커맨드 브리지·동시성·백프레셔·게이트·문서 드리프트 | 79 |
| E buzz 재심 | `[buzz-borrows]` 의 기각·보류를 3.0 렌즈로 재심 + 지난 라운드가 안 읽은 영역 | 79 |

**공통 한계 — 이 문서 전체에 걸린다.**

- **아무도 앱을 실행하지 않았다.** 렌더 결과·체감·성능은 전부 **구조적 추정**이다. "이런
  조건에서 비용이 선형/곱으로 는다"는 코드 판정이지 "느리다"는 관찰이 아니다.
- **빌드·번들·프로파일 측정 0.** CSS 148KB 의 초기 페인트 영향, 청크 크기, 데드락 재현은
  전부 미확인.
- **대비 수치는 `tokens.css` 선언값 계산**이다(`opacity`·겹친 반투명·웹뷰 줌 미반영). 다만
  아래 B-1 의 1.43~2.41 은 오차 범위를 훨씬 넘는다.
- 문서 검증은 표본이다 — 마스터플랜 25개에서 각 3~6개 핵심 주장만 대조했다.
- buzz 는 `--depth 1` 클론이라 `git log` 로 "이 설계가 어떤 사고 뒤에 생겼나"를 캘 수 없었다.

## 발견 — 다섯 갈래

### A. 기록 규율 — 제품 약속 1번이 조용히 새고 있다

README 는 *"에이전트가 일을 마치는 순간 일지는 이미 쓰여 있습니다"* 라고 말한다. 이 저장소
자신의 계측이 그것을 반박한다.

```
종료 세션 280건 중 무기록 신호 164건 (최근 7일 12건)
Today 「일지 없이 끝난 세션」 카드가 계산한 표시 건수: 0
배달 게이트가 실제로 차단한 흔적 (7일): 4건
```

**세 표면이 전부 「프로젝트 전역 journal mtime」이라는 한 근사에 얹혀 있다.**

| 표면 | 판정 재료 | 위치 |
|---|---|---|
| 배달 게이트 (턴을 실제로 막는다) | `find .oculpm/journal -newer $marker` | `plugin/oculpm/hooks/delivery-gate.sh` |
| 미기록 신호 발행 | 같음 | `plugin/oculpm/hooks/session-end.sh` |
| Today 경고 카드 | `newest_journal_mtime(root)` 전역 비교 | `claude_hooks.rs:404-448` |

세션을 2~4개 돌리면 셋이 **동시에**, 전부 미탐 방향으로 무너진다. 세션 A 가 일지를 쓰면
세션 B 의 게이트가 열린다. `session-end.sh` 헤더가 이 한계를 스스로 적어 두었고, 후속으로
미룬 세션 귀속 판정(H3b)은 **앱 소비자만** 만들어졌다.

**결정적인 것 — 고칠 재료가 이미 디스크에 있다.** v2.40.0 이 바로 이 문제를 위해
`AgentRef.session`(`spec.rs:150-155`)과 `Session.agent_sessions`(`session/mod.rs:196`)를
넣었다. 그런데 `agent.session` 을 **읽는 코드가 0곳**이고, `agent_sessions` 의 유일한 소비자는
트레이 팝오버의 뱃지다. **계측을 넣고 그 계측으로 판정을 고치지 않았다.**

카드는 `signals.length === 0` 이면 스스로 숨는다. 그래서 **"깨끗함"과 "가려짐"이 화면에서
구별되지 않는다.**

> 부기 — 무기록 164건 중 몇 건이 "기록했어야 할" 세션인지는 모른다. 신호는 코드 변경 여부를
> 보지 않으므로 읽기 전용 세션이 섞여 있다. **42% 는 상한이고 하한은 4건이다.**
> 또 하나: 일지 537건 중 `agent.session` 을 가진 것이 0건인데, 원인은 설치된 `oculpm-mcp`
> 바이너리가 그 필드를 넣은 커밋보다 오래됐기 때문이다 — **도그푸딩 아티팩트이지 제품
> 결함이 아니다.**

#### A-2. 문서가 없는 화면으로 사용자를 보낸다

- **랜딩 한/영 6곳**(JSON-LD FAQPage · 벤토 셀 · FAQ `<details>` × 양 언어)이 *"Today 의
  「함께 일하는 중」에서 세션을 골라 묶으면"* 이라고 **현재형으로** 안내한다. v2.40.0 이 그
  카드를 Today 에서 제거하고 「세션」 화면으로 옮겼다. `A2aCard.tsx` 없음, `TodayScreenV2` 의
  a2a 참조 0.
  → 활성 플랜의 유일한 미완 항목 `{#readme-koen-landing-today}` 이 대상을 **릴리스 노트로
  잘못 잡고 있다.** 실제 대상은 현재형 FAQ·벤토·구조화 데이터다.
- **FTS5 를 세 면이 주장한다** (`README.md:355`·`README.en.md:355`·`landing/index.html:369`).
  코드에는 없다 — `db/mod.rs:68` 이 *"등록된 적 없이 2026-08-30 폐기"* 라고 적었다. 같은 랜딩
  파일의 JSON-LD `featureList` 는 이미 "정확 일치"로 고쳐져 있다. **사람이 읽는 3면만
  안 고쳐졌다** — 릴리스 5면 규율에서 한 면을 빠뜨린 사고다.
- 영문 랜딩이 **한국어 UI 스크린샷**을 참조한다(`landing/shots/en/` 없음). `/keynote`·`/plugin`
  링크는 한국어판뿐.

#### A-3. 죽은 표면

346개 커맨드 중 어디서도 안 불리는 것 **20개**. 의미 있는 것:

- `commands/overview.rs` **표면 전체**(5개)가 죽었고 `src/features/overview/` 폴더도 없다.
- `oculpm_open_entry_in_editor` — opener-scope 회귀 **3회** 끝에 만든 우회로인데 호출부 0.
  `[opener-scope-recurring]` 메모리가 가리키는 대상이 죽어 있다.
- `acp_stop` — 턴 취소(`acp_cancel`)만 UI 에 있다. **멈춘 어댑터 프로세스를 화면에서 내릴
  길이 없다.**
- `oculpm_reindex_cache` · `oculpm_watcher_stop` — 워처는 켤 수만 있고 끌 수 없다.

#### A-4. done 플랜에서 수거한 이월 백로그 73건

플랜 41개 전수. 그중 약 **25건이 "코드는 들어갔고 사람 눈으로는 안 봤다"** 는 수동 검증
부채였다(`drag-and-drop-round` 6 · `terminal-identity-round` 3 · `skills-star-round` 2 ·
`first-run-and-english-landing {#wizard-eyes}` 등). **UI 손맛이 본질인 라운드가 통째로 미확인인
채 `done` 이다.** 이 저장소에서 「완료」의 실제 의미가 무엇인지 보여 준다.

글리프 위생도 어긋나 있다 — `codex-acp` 는 6건 전부 `[~]` 인데 그중 `{#release-gates}`
(fmt/test/typecheck)까지 미확정이면서 플랜은 `done`. `skill-catalog-round-2` 는 백로그 8건
통째 미착수인데 `done`(→ `archived` 여야 한다).

### B. UI 비주얼 — 무너진 것은 토큰 층이 아니다

**브리프의 가정("CSS 가 무너져 있다")은 틀렸다.** 실측:

- `tokens.css` 347줄 전부 순수 커스텀 프로퍼티 선언, 셀렉터 규칙 0개.
- `!important` 전체 **12개**, 그중 7개가 `prefers-reduced-motion`.
- CSS z-index 24개 중 **20개가 `var(--z-*)`**.
- 중복 셀렉터 3개뿐이고 전부 의도적 분할.
- `pnpm lint:design` **통과** — de-AI 규율 위반 0.

무너진 곳은 다른 데다.

#### B-1. 액센트 배경 위 하드코딩 `#fff` 4곳 — **P0, 고치는 데 20줄**

`--text-on-accent` 토큰이 정확히 이 목적으로 7테마분 존재하는데 네 곳이 무시한다
(`screens.css:572` 플래너 하위작업 체크 · `:407-410` 변경 파일 `A/M/D` 배지 · `:2079` 설정
토글 노브).

| 자리 | light | **dark(기본)** | nord | dracula | **고대비** |
|---|---|---|---|---|---|
| `.sub-check.done` | 4.35 | **1.98** | **2.00** | **2.41** | **1.43** |
| `.dstatus.M` (수정 — 최빈) | **2.80** | **2.16** | **2.16** | **2.16** | **2.16** |

`.dstatus.M` 은 **모든 테마에서** 실패한다. 나머지 셋은 라이트의 `--text-on-accent` 가 마침
`#ffffff` 라서 우연히 통과할 뿐이다. **접근성 목적으로 존재하는 고대비 프리셋에서 1.43:1 로
사실상 사라진다.**

#### B-2. 앱이 두 개의 스타일 방언으로 갈라져 있다

| 방언 | 화면 (정적 className 유틸 출현 수) |
|---|---|
| Tailwind/shadcn | retro **359** · settings **315** · onboarding **196** · graph 138 · skills 101 |
| 토큰 CSS 전용 | discussion 10 · oculpm 6 · today 2 · planner 1 · **diff·search·docs·terminal·sessions·code 0** |

두 타입 스케일이 **12px 한 점에서만 겹친다** — `var(--fs-*)` 는 10~13px 만 정의하고
(`tokens.css:78-80`), Tailwind `text-sm`(14px)은 그 스케일에 **없는 값**이다. 14개 파일이 한
파일 안에서 둘을 섞고, `RetroScreenV2.tsx:355-370` 은 **같은 툴바 한 줄 안에서** shadcn
유틸 버튼과 토큰 프리미티브 `.btn sm` 을 나란히 놓는다.

`App.css:157-171` 의 `@theme inline` 은 radius·shadow·font·ease 를 토큰에 묶었으나
**font-size 는 안 묶었다.**

#### B-3. 한국어 UI 인데 `word-break: keep-all` 이 전체 CSS 에 0회

증상과 대증요법이 **네 벌** 코드에 남아 있다 — `.chip` 주석 *"「수정됨」이 세로로 선다"*,
`.toolbar-title` 주석 *"CJK 가 한 글자씩 세로로 꺾이던 버그"*, `.tbadge` 에 같은 처치 반복,
`.toolbar-actions` 를 가로 스크롤로 도피.

반대로 **가장 긴 한국어 산문 두 곳**은 문자 단위 분해를 켜 두었다 —
`.entry-narrative`(일지 서술 본문 리더)와 `.msg-md`(AI 답변)에 `word-break: break-word`.
근본 처방은 `base.css` 에 `keep-all` + `overflow-wrap: break-word` 짝 2줄이다.

#### B-4. `--text-3` 이 설계 문서가 금지한 용법으로 쓰인다

디자인 SSOT `03-design-system.md:174` 가 이미 ⚠ 로 못박았다 — *"meta/placeholder 전용.
읽혀야 하는 본문에 쓰면 fail. PR-UI 1 에서 grep 으로 점검 후 `--text-2` 로 승격."*
**그 승격이 완료되지 않았다.** `--text-3` 은 CSS 에서 **382회** 쓰이고 고대비를 뺀 **6개 테마
전부에서 AA 미달**(라이트 2.82 · 다크 3.56 · Solarized 2.31)인데, `.empty-hint`(52곳)에
걸려 있다 — 데이터가 없는 화면에서 그건 메타가 아니라 **그 화면의 유일한 문장**이다.

#### B-5. 문법 강조 색이 4벌이고 4개 토큰이 같은 명시도로 충돌한다

`App.css:23`(벤더 github.css 통째) · `App.css:404-472`(다크 재정의) ·
`screens.css:2266-2281`(라이트) · `:2283-2293`(다크). `.hljs-section`·`.hljs-bullet`·
`.hljs-addition`·`.hljs-deletion` 넷이 **동률 명시도**라 주입 순서가 승자를 정한다.
그리고 코드 화면(`code.css` One Light/Dark)과 변경 화면(GitHub 팔레트)이 **다른 체계**라
같은 코드가 화면을 옮기면 키워드가 보라→빨강으로 바뀐다. 둘 다 `[data-theme]` 만 보므로
**프리셋 5종에서는 양쪽 다 틀린다.**

### C. UX — 첫 5분이 사실과 다르게 말한다

#### C-1. 온보딩의 시제가 틀렸다 — **P0**

마법사 마지막 판: *"기록 규칙을 폴더에 심었습니다. 에이전트가 일을 마칠 때마다 일지가
쌓입니다."*(`ko.ts:3467-3468`). 그 시점에 `create_project` 는 **DB 행 하나만** 만든다
(`commands/project.rs:70-78`). `.oculpm/`·`AGENTS.md`·`.gitignore` 는 **「프로젝트 열기」때**
심긴다(`ProjectTab.tsx:125`). Esc 로 나가면 아무것도 안 심긴 채 심었다고 말하고 끝난다.

이어서 Today 빈 상태: *"평소처럼 코딩 에이전트로 작업하면 Ocul-PM이 자동으로 일지를
작성합니다."*(`ko.ts:982`). 그 시점에 켜져 있는 자동화가 **하나도 없다** —
`auto_reconcile: false`, `auto_journal_draft: false`, `automation.schedules/watchers: false`.
그리고 준수율을 실제로 올리는 **Claude Code 플러그인은 온보딩 어디에도 언급이 없다.**
안내는 `설정 → ocul-pm → 연동` **3단 깊이**뿐이고, `claudePluginStatus` 를 읽는 표면이
그 블록과 스킬 탭 둘뿐 — **미설치를 알리는 토스트·카드·배지가 0곳**이다.

**새 프로젝트에서 17화면 중 첫날 살아 있는 것은 5개다.**

1. `satisfies Record<AgentActivityRenderClass, Presenter>` 로 **누락을 컴파일 에러**로.
2. 분류가 transport 가 아니라 **semantics** — `parseBuzzCliCommand` 가 셸 명령 문자열을
   토크나이즈해 자기 CLI 호출을 찾아낸다. `buzz messages send` 가 셸로 돌면 「명령 실행」이
   아니라 **「메시지를 보냈습니다」**로 그린다.
3. **개입 지점은 절대 안 접는다** — *"Messages, errors, permissions, and status/lifecycle rows
   never join either pass, so intervention points stay visible."*
4. **항상 있는 바닥** — `RawEventRail.tsx` 49줄이 원본 JSON 을 `<details>` 로 전부 보여 준다.
   추상화가 틀려도 도망갈 데가 있다.

**우리에게 정확히 없는 것**: `acpTurns.ts:346-356` 이 `kind: event.tool_kind` 를 **그대로**
담는다 — 의미 층이 없다. `TOOL_ICON` 8칸, 모르는 종류는 `Code2` 폴백. **결과:
`session-shim-cli` 로 PATH 에 `oculpm` 을 심어 놓고 그것이 도는 것을 화면이 모른다.**
`oculpm journal write` 는 「명령 실행 + 터미널 아이콘」이다 — **「일지를 썼다」가 화면 어휘에
없다.** 묶기도 없어서 `TraceRow.tsx:62-66` 주석이 문제를 자백한다: *"똑같이 생긴 스무 줄이

우리 판의 어휘는 buzz 를 베끼지 않는다 — `oculpm-journal · oculpm-plan · oculpm-a2a` **셋이

#### E-2. N1 유출 경로 인벤토리 — **이번 조사 최대 발견**

`desktop/src-tauri/src/egress_guard.rs` 는 **58줄**, 그 테스트는 **483줄**이다. 모듈 독이
경계 8곳을 표로 열거하고 닫는다: *"The **inventory-completeness test** asserts that every
`/events` URL-construction site in the tree calls this guard, so **a new submission path fails
the build until it is wired.**"* **값어치는 가드가 아니라 인벤토리 테스트다.**

우리 상황:
1. **인벤토리 테스트 0건.**
2. **모듈 독이 이미 드리프트했다** — `oculpm/redact.rs:15-19` 는 *"세 곳에 wired"* 라고
   적혀 있고 실제 호출부는 **19개 파일**이다. **문서는 3, 현실은 19. 아무도 안 세고 있다.**
3. **정작 데이터가 기기를 떠나는 경로엔 0건이다** — `grep -rn "redact" src-tauri/src/llm/`
   → **0**. RAG 코드 조각은 `searchChunks` → `buildContextSystem` → 프롬프트로 **마스킹 없이**
   간다.

공정하게: 이건 부분적으로 *의도*다(`redact.rs:10-13` 이 범위를 "body/diff-hunk content only,
never path or identifier text"로 못박았다 — 오탐 방지). **결론은 "redact 를 LLM 경로에
붙여라"가 아니다.** 결론은 다르다 — **우리 제품 약속이 「아무것도 기기 밖으로 안 나간다」인데
지금 그 문장을 지키는 기구가 없다.** 사람의 주의력뿐이고 문서는 이미 3 vs 19 로 틀렸다.
F2(프롬프트 경계)·F3(해시 체인)과 **정확히 같은 계보** — 「부탁을 기구로」.

**넘지 않고 되는 것: 브랜치 축.** buzz 의 *"When you create a branch, Buzz creates a channel…
The conversation becomes the permanent record of why that code exists"* 는 팀 기능이 아니라
**우리 제품의 정의에 가깝다.** 우리 축은 날짜+타입 폴더이고 브랜치는 스냅샷에 **값으로만**
잡힌다(`spec.rs:294`) — 조직 축이 아니다. `feat/x` 에서 사흘간 만든 일지 5건·플랜 항목 7개를
「이 브랜치의 이야기」로 보여 주는 화면이 없다. **git 은 이미 로컬에 있고 `git.rs` 가 읽는다 —
새 저장 형식도 네트워크도 필요 없다.**

**서명은 안 한다.** F3 의 한계 문장(*"감사이지 서명이 아니다"*)을 화면에도 유지한다. 그건
약점 고백이 아니라 **제품 경계의 선언**이다.

## 모순과 미해결

정직하게 남긴다.

1. **요청 vs B 의 결론.** 요청은 *"더 미학적, 공학적 설계를 한 UI 디자인"* 이었다. B 는

   곳 닫기**여야 한다."* 근거는 약하지 않다(토큰 층 규율 정상, `lint:design` clean, 프리셋
   축 정상 작동). **이건 사용자 결정 사항이다** — 아래 `{#decide-redesign}`.
2. **IA 안 A vs 안 B.** C 는 보수안(17→15행, 저장값 무손실)을 권했지만, D 의 "3.0 의 새 화면은
   정의상 가장 덜 익은 코드"와 E 의 라우터 제안(N3)은 급진안 쪽 비용을 낮춘다. **E 는
   "라우터는 R1(활동 의미층) 뒤가 싸다"고 순서를 제안했다.**
3. **에러 바운더리 개수** — D 는 3개(설정 2 + 탭 1), E 는 "최상위에 없다". 확정된 공통분모만
   위 E-3 부기에 적었다.
4. **A 가 지목한 3.0 1번 문제(기록 귀속)와 D 가 지목한 것(ESLint·백프레셔)이 다르다.**

5. **성능 주장은 전부 미측정.** D-2·D-3 의 "터진다"는 구조 판정이다. 실제 체감은 훨씬 나을

   자리가 확정된다.

## 후보 해결 방안

### 방안 A — 기구 우선: 「부탁을 기구로」 한 라운드 {#opt-mechanism}

3.0 을 **제품 약속을 지키는 기구**의 라운드로 정의한다. 시각·IA 는 손대지 않는다.

담을 것: 기록 귀속 판정 하나로 통합(세 표면 → 순수 판정 함수, mtime → `agent.session`) ·
유출 경계 인벤토리 테스트 · 플래너 CAS 필수화 + 재시도 프로토콜 · ACP in-flight 가드 +
RAII 종료 표식 · F6 fail-open 수정 · 자동화 유출 배지.

- **장점** 제품의 존재 이유를 직접 지킨다. 각 항목이 작고 독립적이라 나눠 낼 수 있다.
  "3.0" 이라는 이름에 걸맞은 **성격의 변화**(설득 → 기구)가 있다.
- **단점** 사용자가 요청한 넷 중 **UI·UX 둘을 통째로 미룬다.** 릴리스 노트가 "안 보이는 것만
  고쳤다"가 된다. 3.0 이라는 번호에 대한 기대와 어긋난다.
- **비용** 중. 항목당 소~중, 합쳐 커밋 8~12개.

### 방안 B — 표면 우선: 보이는 것부터 {#opt-surface}

IA 재편(C 안 A) + 활동 의미층(E R1) + 시각 확정 결함(B-1·B-3·B-5 부분) + 첫 5분 정정
(C-1) + ⌘W 가드(C-2).

- **장점** 요청에 정면으로 답한다. 매일 보이는 것이 바뀐다. E-1 이 밝혔듯 **활동 의미층은
  1,000~1,400줄로 예상보다 싸고**, 그 작업이 `AcpConversation.tsx` 2,192줄 분해와 한 몸이라
  부채도 함께 준다.
- **단점** D 의 정지작업을 건너뛰면 **배로 든다** — ESLint 없이 새 화면을 쓰면 D-1 계열이
  다시 생기고, `screens.css` 445 접두사에 화면을 더 얹고, 일지 타임라인 상한 없이 일지
  스키마를 건드리면 내내 자기 발에 걸린다. A 의 기록 귀속은 그대로 샌다.
- **비용** 중~대.

### 방안 C — 정지작업 먼저, 그 다음 두 기둥 {#opt-groundwork-two-pillars}

3.0 을 **3단**으로 나눈다.

**0단 — 무논쟁 정지작업 (며칠).** 논쟁의 여지가 없고 회수율이 확인된 것만.
`docs/` 색인 + 아카이브 배너 + 뒤집힌 결정 6개 인라인 주석 · `CLAUDE.md` 재작성(특히
마이그레이션 등록 단계) · ESLint + `react-hooks` 도입(경고 래칫으로 시작) ·
`rust-toolchain.toml` 핀 + `cargo-deny` · 화면 단위 ErrorBoundary + localStorage try/catch ·
ACP in-flight 가드 + RAII 종료 표식 · F6 fail-open · `#fff` 4곳 · `keep-all` 2줄 ·
릴리스 표면 정정(랜딩 6곳 + FTS5 3면 + 영문 스크린샷).

**1단 — 기둥 하나: 기록이 진짜로 남는다.** A 의 처방 전부 + 유출 인벤토리 테스트 +
플래너 CAS + 일지 타임라인 상한 + 워처 백프레셔.

**2단 — 기둥 둘: 보이는 것이 정직하고 읽힌다.** 활동 의미층(E R1) + IA 재편(C 안 A) +
`uiV2View` 마이그레이션 함수 + 조용한 실패 6화면 + 첫 5분 정정 + ⌘W 가드 + 스타일 방언 수렴
(`@theme inline` 에 `--text-*`·spacing·z 묶기).

- **장점** 두 감사의 1번 문제가 **순서로** 풀린다. 0단이 나머지 전부의 비용을 낮춘다
  (특히 ESLint·문서·ErrorBoundary). 각 단이 독립 태그로 나갈 수 있어 3.0 을 한 번에 안 내도
  된다. 요청 넷을 전부 덮는다.
- **단점** 가장 길다. 0단은 릴리스 노트에 쓸 게 별로 없다. 2단의 IA 재편은 ⌘번호 근육을
  깬다(⌘3·⌘5·⌘6·⌘0 의 뜻이 바뀐다).
- **비용** 대. 그러나 **분할 가능**하고, 그게 이 방안의 요지다.

### 방안 D — 전면 리디자인 {#opt-full-redesign}

새 비주얼 언어를 정하고 화면을 다시 그린다. 요청의 문자 그대로.

- **장점** 3.0 이라는 번호에 가장 걸맞다. 두 스타일 방언 문제를 근본에서 없앨 수 있다.
- **단점** **B 가 명시적으로 반대한다.** 토큰 층은 규율이 서 있고 `lint:design` 은 clean 이며
  프리셋 축은 정상 작동한다 — 뒤집을 근거가 없다. Tailwind 를 걷어내면 **1,100곳 이상**을
  손으로 옮겨야 하고 그 화면들은 CSS 파일이 아예 없어 새로 써야 한다(retro 는 0줄).
  반대로 토큰 CSS 를 버리면 프리셋 5종 × 액센트 6색 축과 `termTheme.ts` 의 xterm 팔레트
  생성을 새로 짜야 한다. 그리고 **B 가 확정한 P0/P1 다섯 개는 리디자인으로 안 없어진다** —
  하드코딩 `#fff` 도, `keep-all` 부재도, 문법 색 4벌도 새 디자인에 그대로 따라온다.
- **비용** 최대. 회귀 위험 최대.
- **부분 채택 가능한 것** — 리디자인 없이도 "새로워 보이게" 하는 지렛대가 둘 있다:
  ① 활동 의미층(E R1)이 AI 화면의 인상을 바꾼다, ② IA 재편(C)이 사이드바를 정리한다.
  **둘 다 방안 C 의 2단에 이미 있다.**

## 사용자가 결정해야 할 것

1. **3.0 의 성격** — 기구/표면/양쪽(방안 A·B·C·D 중).
2. **전면 리디자인 여부** — B 의 반대를 받아들일 것인가, 뒤집을 것인가. 뒤집는다면 그건
   3.0 이 아니라 **별도 라운드**여야 한다는 게 B 의 부수 의견이다.
3. **IA 재편 범위** — C 의 안 A(보수, 저장값 무손실) vs 안 B(급진, 3면). **어느 쪽이든
   `uiV2View` 마이그레이션 함수가 선행**이다.
4. **경계** — 팀·원격·서명은 E 가 반대했다. **브랜치 축**만 채택할 것인가.
5. **수동 검증 부채 25건** — 3.0 에 "육안 확인 라운드"를 넣을 것인가, 별도로 뺄 것인가.
6. **즉시 분리 출고** — 릴리스 표면 거짓(랜딩 6곳·FTS5 3면·영문 스크린샷)과 `#fff` P0 는
   3.0 을 기다릴 이유가 없다. **2.40.x 로 먼저 낼 것인가.**

## 결론

**채택 — 방안 C(정지작업 → 두 기둥)를 뼈대로 하고, 방안 D(전면 리디자인)는 기각하되 그 목적은
지렛대 둘로 대신한다. 그리고 「오류 수정 1순위」 제약에 맞춰 라운드를 릴리스 셋으로 나눈다.**

### 왜 이 조합인가

1. **게이트가 오류보다 먼저다.** "찾은 오류를 고친다"를 문자 그대로 실행하면 D-1 계열(구독
   누수 15곳·떠 있는 프로미스 110곳)은 **고쳐도 다시 생긴다** — 막는 게 없기 때문이다.
   ESLint 는 그 결함을 *찾아 주는 도구*이기도 하므로 수정 대상이 아니라 **수정의 선행**이다.
   같은 이유로 `rust-toolchain` 핀·`cargo-deny`·F6 fail-open 이 1번 릴리스에 들어간다.
2. **지금 보이는 거짓은 3.0 을 기다릴 이유가 없다.** 랜딩 6곳이 없어진 화면으로 안내하고,
   FTS5 를 세 면이 주장하고, 다크에서 대비 1.98:1 인 `#fff` 가 네 곳이다. 전부 소~중 비용이고
   3.0 은 몇 주가 걸린다. → **v2.41.0 으로 먼저 낸다.**
3. **전면 리디자인은 기각한다** — B 의 근거를 받아들인다(토큰 층 규율 정상, `lint:design`
   clean, 프리셋 축 정상, 그리고 **확정 P0/P1 다섯 개는 리디자인해도 그대로 따라온다**).
   **다만 "새로워 보임"을 포기하지 않는다.** 매일 보이는 두 면을 바꾸는 지렛대가 둘 있고,
   둘 다 리디자인보다 싸며 부채를 함께 줄인다:
   - **활동 의미 층** — AI 화면이 「명령 실행」 스무 줄에서 「일지를 썼습니다」로 읽힌다.
     참조 구현이 1,121줄이고, 그 작업이 `AcpConversation.tsx` 2,192줄 분해와 한 몸이다.
   - **IA 재편(안 A)** — 사이드바 17행 → 15행, ⌘번호가 실사용 빈도와 맞고, 이름 충돌이 사라진다.
     저장된 `uiV2View` 를 하나도 안 버린다.
4. **3.0 의 헤드라인은 넷이다** — 기록이 진짜로 남는다 · AI 화면이 읽힌다 · 사이드바가
   정리된다 · **브랜치의 이야기**(경계를 넘지 않는 유일한 신기능).
