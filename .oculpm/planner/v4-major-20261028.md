사용자 목표 셋(Rieseberg 「How to be more ambitious」 적용 · 하드 유저와 라이트 유저가 같이 쓰는 단순한 UI · 어떤 프로젝트든 에이전트가 최상의 결과)과 4.0 실효성 감사. 조사 결론: 새로 짜는 것보다 고치는 것이 싸다 — 파일 규격·MCP·워처·서명/업데이트/CI 가 fix 이력의 대부분을 흡수한 자산이고, 핵심 4화면만 같은 백엔드 위에서 다시 그린다.

**완료 조건:** 앱이 Today·작업 일지·계획·변경·설정만 남고(검색·스킬·논의·브랜치·트레이·테마 프리셋·앱 안 LLM·자동화·코드 색인 제거), 하루 60건 쓰는 사용자와 3건 쓰는 사용자가 같은 Today 의 「확인할 것」만 보고 다음을 결정하며, 템플릿 v20·inception·next(until-done)가 어떤 새 프로젝트에서도 판정(확인 명령)을 먼저 깔게 하고, v4.0.0 이 CI 초록으로 main 에 합류한다
**확인 명령:** pnpm typecheck && pnpm test && pnpm lint && pnpm build && (cd src-tauri && cargo test --locked)
