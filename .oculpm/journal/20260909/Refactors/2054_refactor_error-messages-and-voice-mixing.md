## 동기

### 「명사 실패: 영문 원문」

`{error}` 를 그대로 보간하는 문자열이 104건이고, 그중 41건이 `"압축 실패: {error}"` 꼴이었다. `tError()` 가 못 번역한 IO 오류가 뒤에 그대로 붙으면 한국어 UI 에 이렇게 뜬다.

```
압축 실패: Could not open database: no such file or directory (os error 2)
```

이건 로그를 UI 에 붙여넣은 것이지 메시지가 아니다.

### 한 문자열 안에서 화자가 바뀐다

먼저 감사 수치를 다시 쟀다. **「하세요」(명령형 해요체)와 「합니다」(평서 합쇼체)가 한 문장에 있는 건 한국어 UI 의 정상 조합**이다 — 서법이 다르다. 그걸 빼고 **평서문끼리** 갈리는 것만 세니 24건이었다 (감사는 28건이라 했고, 명령형까지 세면 66건이 나온다).

```
이 컴퓨터에만 남습니다 — 원장에는 쓰지 않아요
읽은 뒤에 이 문서가 디스크에서 바뀌었어요 (다른 세션이나 에이전트가 고쳤습니다). 편집 내용은 그대로 있습니다.
```

## 변경 요약

**에러 41건** — 무엇이 안 됐는지를 한국어 문장으로 먼저 말하고 원문을 뒤로 민다.

```
삭제 실패: {error}      →  계획을 지우지 못했어요 — {error}
압축 실패: {error}      →  데이터베이스를 압축하지 못했습니다 — {error}
PTY 시작 실패: {error}  →  터미널을 시작하지 못했습니다 — {error}
```

원문을 지우지는 않았다 — 진단 정보이고, 접힌 상세로 내리려면 토스트에 없는 UI 가 필요하다. 그건 별도 항목으로 남는다.

부수 발견: `graph.previewFailed` 의 값이 `"// 미리보기 실패: {error}"` 였다 — 주석 기호가 사용자에게 보이는 문자열에 들어가 있었다.

**말투 24건** — 각각 그 네임스페이스의 우세한 말투로 맞췄다(`plan.*` 해요 14:2 · `op.*` 합쇼 44:0 처럼 대개 뚜렷하다). 새로 쓴 에러 41건도 같은 규칙을 따랐다.
