# /oculpm:next

계획을 핸들로 쓰는 구현 루프. 한 바퀴 = 리프 하나.

1. **고르기** — `plan_status` 로 활성 플랜의 미완 리프를 본다 (하위를 가진 부모는 롤업이라 제외). `[~]` 는 **다른 세션이 잡은 것**이라 건너뛴다 — `$ARGUMENTS` 로 그 항목 id 를 지정했을 때만 예외. 남은 `[ ]` 중 문서 순서상 첫째를 잡고 무엇을 잡았는지 먼저 알린다. `[ ]` 가 없으면: `[~]` 만 남았으면 그 목록을 보여 주고 id 로 지정하라고, 그것도 없으면 "활성 플랜의 항목이 모두 끝났습니다" 로 끝낸다.
2. **잡기** — 구현 전에 `plan_update(status: in_progress, note: "잡음")` 으로 `[~]` 를 먼저 쓴다 (`base_hash` 는 1의 `plans[].hash`). 해시가 어긋나면 다시 읽는다 — 그새 다른 세션이 잡았으면 다음 리프로.
3. **목표** — 그 플랜의 `done_when`·`check` 를 읽는다. 항목의 동사구가 이 리프의 완료 기준, 완료 조건이 그 너머의 목표다. 최소 해석으로 가장 작은 것을 만들지 말고 완료 조건을 참으로 만드는 쪽을 고른다 (빈 상태·오류 상태·연결까지). 추측이 아니라 원재료(로그·실데이터·재현)에서 시작한다.
4. **판정** — 확인 명령을 돌린다 (없으면 프로젝트의 테스트/빌드/린트). 「통과했다」가 아니라 **결과 끝 줄**(N passed · exit 0)이 증거다. 초록이어도 가능하면 실제로 띄워 한 번 써 본다 (서버면 curl, 화면이면 스크린샷).
5. **기록** — `journal_write`(검증 칸에 그 결과 끝 줄) → `plan_update` 로 항목 상태 (`base_hash` 는 직전 `plan_update` 응답의 hash). 확인 명령을 돌렸으면 note 를 `판정 ✓ <결과 끝 줄>` 또는 `판정 ✗ <결과 끝 줄>` 로 시작한다 — 다음 세션의 시작 훅이 「마지막 판정」으로 싣는다. `warnings` 가 오면 그대로 따른다. 못 끝내면 `[!]` + 무엇이 막았는지 note, 실패한 접근은 error 일지로 — 다음 세션의 원재료다.

## until-done

`$ARGUMENTS` 에 `until-done` 또는 `끝까지` 가 있으면 5 뒤에 묻지 말고 1로 돌아간다. 기본 자세는 "풀 수 있다, 계속하라" — 어려우면 다음 방법을 쓴다. 멈추는 것은 넷뿐:

- **판정 통과** — 플랜의 확인 명령이 통과하고 완료 조건이 참이다 (닫기는 사용자 결정, 남은 리프는 보고만).
- **`[!]` 막힘** — 바깥 것(권한·키·외부 서비스)이 막았다.
- **사용자 결정 필요** — 범위·제품 판단처럼 네가 정할 수 없는 것.
- **같은 접근 두 번 실패, 바꿀 접근도 없음** — 무엇을 시도했고 숫자가 어디서 멈췄는지 남긴다.

리프마다 일지 + `plan_update` 는 그대로다. 멈출 때 한 줄: 멈춘 이유 · 마지막 판정 · 남은 리프 수.

until-done 이 아니면 다음 리프가 남았을 때 이어서 돌지 묻는다.
