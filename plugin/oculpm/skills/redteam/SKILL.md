# /oculpm:redteam — 플랜·일지의 반대편

"숏셀러처럼 **써라**"가 아니라 숏셀러가 **하는 일**을 하세요. 숏셀러는 글을 쓰지 않습니다 — 숫자를 다시 세고, 주장을 원재료와 대조하고, 틀리면 돈을 잃습니다. 이 스킬의 산출물은 **논증이 아니라 재현된 반례**입니다.

## 대상

인자가 없으면 활성 플랜 중 가장 최근에 갱신된 것. `/oculpm:redteam <plan_id>` 또는 일지 경로를 주면 그것.

## 절차 (형식 강제)

1. **주장 목록** — 플랜의 `**완료 조건:**` 과 완료(`[x]`) 항목, 일지의 「검증」 칸에서 **검증 가능한 주장**만 뽑는다 (한 줄 = 한 주장). 의견·계획은 뽑지 않는다.
2. **원재료로 가기** — 주장마다 그것을 뒷받침한다는 **원재료**(테스트 파일·명령·로그·DB 행·git diff)를 찾는다. 요약·일지 문장·커밋 메시지는 원재료가 아니다.
3. **직접 돌린다** — 테스트·린트·빌드·스크립트를 **실제로 실행**하고 exit code 와 숫자를 받는다. 돌릴 수 없는 주장은 「검증 불가」로 분류한다 — 그것도 발견이다.
4. **가정을 뒤집는다** — "이 주장이 틀렸다면 어디서 먼저 드러나는가"를 하나 골라 그 자리를 본다 (경계값·빈 입력·동시 실행·다른 OS·오래된 데이터).
5. **바깥 심판만 인용** — 네 판단("문제없어 보인다")은 결과에 쓰지 않는다. 결과 줄에는 명령·파일·숫자만.

## 결과 형식 (강제 — 자유 산문 금지)

```
REDTEAM <대상> · 주장 N · 반례 N · 검증 불가 N

반례
<file>:L<line> 또는 <명령>: <주장> ↔ <실제로 나온 것>. <재현: 한 줄 명령>.

검증 불가
<주장>: <왜 돌릴 수 없는가> → <무엇이 있으면 돌릴 수 있는가>.

유지된 주장
<주장>: <무엇이 그것을 보여줬나 (명령·숫자)>.
```

- 반례가 0 이면 "반례 0" 이라고 쓰고 **유지된 주장**에 근거를 전부 적는다 — 빈 보고는 금지.
- 반례는 **고치지 않는다**. 고칠지는 사용자가 정한다. 사용자가 고치라고 하면 그때 `/oculpm:next` 로.
- 결과는 `.oculpm/discussion/` 에 토의 문서로 남기지 **않는다** — 사용자가 요청할 때만 `journal_write`(type: chore, 제목 「레드팀 — 대상」)로 기록한다.

## 금지

- 역할극 문체("숏셀러로서 저는…"). 하는 일만 한다.
- 돌리지 않은 명령의 결과를 추정하기.
- 대상 플랜·일지의 수정. 읽기와 실행만.
