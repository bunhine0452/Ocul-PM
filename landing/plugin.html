커맨드 · MCP 도구 · 스킬 — 전체 표면

플러그인 하나가 프로젝트 시작 → 설계 → 구현 루프 → 보고까지 커버합니다. 이 페이지는 플러그인이 제공하는 모든 것의 살아있는 문서입니다 — 새 커맨드가 생기면 여기가 함께 갱신됩니다 (저장소 테스트로 강제).

/plugin marketplace add bunhine0452/Ocul-PM
/plugin install oculpm@oculpm
권장 흐름

프로젝트 시작부터 구현 루프까지

/oculpm:project_init→ /oculpm:inception→ /oculpm:next(리프가 끝날 때까지 반복)→ /oculpm:standup

기능 추가는 /oculpm:inception(계획만 확장) 또는 바로 /oculpm:next 부터 — 인셉션의 인터뷰·리서치는 낯선 영역일 때만 다시 돕니다.

슬래시 커맨드 5종

타이핑 한 줄로 부르는 것

/oculpm:project_init새 저장소에서 한 번

이 프로젝트를 ocul-pm 추적 대상으로 초기화합니다 — .oculpm/(기록 저장소), AGENTS.md(에이전트 기록 규칙), .gitignore 보호 블록이 생깁니다. 커맨드를 직접 실행한 것이 곧 명시적 동의라 재확인 없이 진행되고, 이미 추적 중이면 누락 구성만 보완합니다. 앱은 없어도 됩니다.

/oculpm:inception새 프로젝트/기능 영역 설계

project-inception 스킬로 설계를 시드합니다: 최소 문제 파악 → 웹 리서치로 환경 탐색 → 근거(버전·출처)가 실린 선택지로 사용자와 사양 확정 → plan_create 로 3단계 상세 계획 → EVALS.md 완료 정의 → 초기 .claude/rules. 아이디어를 인자로 줄 수 있습니다: /oculpm:inception 할 일 앱을 만들고 싶어

/oculpm:next구현 루프 — 반복 실행

활성 플랜의 다음 미완 리프를 잡아 구현 → 게이트 확인 → 일지 → 플랜 갱신 한 사이클을 돕니다. 앱 플래너의 ▶실행과 같은 역할의 플러그인 대응물입니다. 특정 항목을 지정하려면: /oculpm:next login-happy-path

/oculpm:standup보고가 필요할 때

오늘 일지와 플랜 진행을 모아 스탠드업 요약(한 일 / 진행 중·막힘 / 다음)을 만듭니다.

/oculpm:help뭐가 있는지 잊었을 때

플러그인 표면 전체(커맨드 5·MCP 도구 5·스킬 5·훅)를 레퍼런스 카드 한 장으로 보여주고, 지금 상황에 맞는 다음 한 걸음을 추천합니다.

MCP 도구 5종

에이전트가 기록에 쓰는 구조화 도구

에이전트가 마크다운 규격을 흉내 내는 대신 도구로 기록합니다 — 경로·frontmatter·항목 id 규격은 서버가 보장합니다. 모든 도구는 .oculpm/ 이 있는 추적 프로젝트에서만 동작합니다 (유일한 예외: project_init).

도구하는 일
journal_write작업 단위(버그/기능/리팩토링/에러/잡일) 하나가 끝날 때마다 일지 1건을 규격대로 기록.
plan_status활성 플랜의 항목·상태를 조회 — "지금 어디까지 됐나"의 근거.
plan_update플랜 항목의 상태를 갱신하고 plan-log 를 남김. 하위를 가진 부모는 롤업 자동이라 직접 갱신 거부.
plan_create새 계획을 3-depth(마일스톤→작업→하위 작업)로 생성 — frontmatter·id 규격 서버 보장.
project_init미추적 저장소의 추적 시작 — 사용자의 명시적 요청·확인(confirm)이 있을 때만. 심볼릭 링크 거부·홈 디렉터리 가드.
스킬 5종

상황에 맞게 스스로 발동하는 방법론

스킬언제 · 무엇
oculpm-journal기록 규격의 풀 스펙 캐리어 — 일지·플랜 규칙의 세부가 필요할 때 로드.
project-inception새 프로젝트/기능 영역 킥오프 — 리서치→사양 확정→3-depth 계획→EVALS→rules 시드 (/oculpm:inception 이 부르는 그 스킬).
self-audit"다 했다"고 말하기 전에 요구사항 대조·게이트 실행·diff 재검토를 강제.
run-evalsEVALS.md 의 완료 정의를 실제로 실행·채점하고 기록 표에 추가 — 앱 회고 화면이 추이를 그립니다.
tdd-workflow실패하는 테스트 먼저 → 최소 구현 → 그린 → 리팩토링 사이클을 강제.

안전 계약(무엇을 읽고 쓰고 절대 하지 않는지)은 저장소의 플러그인 계약 문서에 테스트와 함께 고정돼 있습니다. 훅은 네트워크 없는 로컬 append 한 줄이고, 대화 로그가 담기는 .oculpm/hooks/ 는 gitignore 관리 블록이 커밋을 막습니다. 여기에 배달 게이트가 하나 더 있습니다 — 코드 변경이 있는데 일지 없이 세션을 마치려 하면 세션당 한 번 에이전트에게 일지 작성을 지시합니다 (규칙 주입만으로는 헤드리스 세션 기록 준수가 0% 였던 자체 벤치 실측이 근거).

스킬 샵 — 제3자 카탈로그 25종 (앱)

스택을 감지해서 검증된 스킬을 추천

ocul-pm 앱의 스킬·규칙 → 샵 탭은 프로젝트의 매니페스트(package.json·Cargo.toml·pyproject 등)로 스택을 감지해, 아래 카탈로그에서 맞는 스킬을 추천합니다. 전부 MIT 제3자 스킬(ECC · ponytail)의 커밋 고정 사본 — 원문 무수정, 런타임 네트워크 0. 설치하면 .claude/skills/ 에 들어가며 이는 Claude Code 네이티브 기능이라 플러그인 없이도 동작합니다.
