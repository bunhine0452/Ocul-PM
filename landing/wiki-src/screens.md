Ocul-PM 의 화면은 여덟입니다. 위쪽 「기록」은 에이전트가 무엇을 했는지 쌓이는 곳이고, 아래쪽 「도구」는 그 기록 옆에서 찾고 관리하는 곳입니다. 에이전트 자체는 **여러분의 터미널**에서 돕니다 — 앱 안 터미널 · 편집기 · 에이전트 화면은 2026-10-28 에 걷었습니다.

사이드바 순서 = `⌘` 번호 순서입니다 (`⌘1` ~ `⌘8`).

화면에는 **등급**이 있습니다 ([약속 문서](https://github.com/bunhine0452/Ocul-PM/blob/main/docs/PROMISE.md)): 「기록」의 오늘 현황 · 작업 일지 · 변경 · 플래너가 **핵심**(이 앱이 약속하는 것), 문제 해결 · 브랜치 · 검색 · 스킬·규칙은 **뷰어**(열리고 보여 주고 깨지지 않는 것까지)입니다.

## 기록

| 화면 | 키 | 하는 일 |
|---|---|---|
| **오늘 현황** | `⌘1` | 오늘 하루의 요약 — 활동 링, 커밋 그래프, 에이전트별 기여, 정직성 감사 |
| **작업 일지** | `⌘2` | 쌓인 일지의 타임라인. 날짜별로 접히고, 각 일지는 서술 + 변경 diff 2단 |
| **변경** | `⌘3` | 지금 작업 트리의 변경을 줄 단위로. 일지·계획별로 묶어서도 볼 수 있고, 바뀐 파일을 import 하는 「영향 받는 파일」도 짚음 |
| **플래너** | `⌘4` | 지금의 계획. 에이전트가 스스로 갱신하는 살아있는 문서 |
| **문제 해결** | `⌘7` | 결정 전에 옵션을 늘어놓고 비교하는 토의 문서 |
| **브랜치** | `⌘8` | 이 브랜치에서 무슨 일이 있었나 — 커밋·일지·계획·바뀐 파일과 기록률 |

일지와 플래너는 이 앱의 두 기둥입니다 — 각각 [작업 일지](/wiki/journal)와 [플래너](/wiki/planner)에서 자세히 다룹니다.

## 도구

| 화면 | 키 | 하는 일 |
|---|---|---|
| **검색** | `⌘5` | 의미 검색 · 심볼 · 정확히 일치 — 세 가지 모드 |
| **스킬·규칙** | `⌘6` | 에이전트에게 주입되는 스킬·규칙·훅을 한자리에서 |

:::tip
검색 결과의 「열기」는 설정의 **외부 편집기** 명령(VS Code · Cursor …)으로 그 파일 그 줄을 엽니다. 앱 안 편집기는 없습니다.
:::

## 코드 검색 — 세 모드의 차이

| 모드 | 언제 | 어떻게 찾나 |
|---|---|---|
| **의미 검색** | "로그인 실패를 어디서 처리하지?" | 로컬 임베딩으로 뜻이 가까운 조각을 찾습니다 |
| **심볼** | 함수·클래스 이름을 알 때 | tree-sitter 로 뽑아 둔 심볼 표에서 |
| **정확히 일치** | 오타·상수·문자열 추적 | 문자열 그대로 |

의미 검색의 인덱싱은 **전부 로컬**입니다 — 코드가 밖으로 나가지 않습니다. 프로젝트를 처음 열 때 한 번 인덱싱하고, 그 뒤로는 바뀐 파일만 갱신합니다. 기본값은 코드만 훑지만 「문서 포함」을 켜면 `.md`·`.txt` 도 결과에 들어옵니다.

## 문제 해결 (토의)

일지가 *지나간 일*이고 플래너가 *현재 계획*이라면, 토의는 **결정 직전**입니다. 옵션 A·B·C 를 늘어놓고 장단점을 적어 고르는 문서고, `.oculpm/discussion/<이름>/discussion.md` 에 남습니다.

:::note
에이전트는 여러분이 "옵션을 비교하자 / 이 문제를 정리하자" 고 **명시적으로 요청할 때만** 토의 문서를 만듭니다. 평범한 작업에는 일지와 플래너면 충분하기 때문입니다.
:::
