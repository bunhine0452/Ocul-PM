## 일지가 안 쌓여요

순서대로 확인하세요:

1. **추적 중인 프로젝트인가요?** 프로젝트 루트에 `.oculpm/` 폴더와 `AGENTS.md` 가 있어야 합니다. 없다면 시작 화면에서 폴더를 다시 불러오세요.
2. **터미널 Claude Code 인가요?** AGENTS.md 만으로는 모델이 기록을 잊을 수 있습니다. [플러그인(훅 브리지)을 설치](/wiki/claude-code)하면 자동이 됩니다.
3. **규칙이 오래됐나요?** 설정 → ocul-pm → 에이전트 탭에서 **규칙 다시 보내기**로 AGENTS.md 를 최신 규격으로 갱신할 수 있습니다.
4. **다른 에이전트(Cursor 등)인가요?** 설정에서 해당 에이전트의 규칙 파일을 켜야 합니다. AGENTS.md 를 읽는 에이전트라면 그대로 동작합니다.

## 앱 안 Claude Code 에서 `/plugin` `/mcp` `/login` 이 안 돼요

정상입니다 — ACP 프로토콜은 CLI 의 대화형 명령을 나르지 못합니다. Claude Code 화면 우상단 **터미널 버튼**으로 진짜 `claude` 를 열어 거기서 실행하세요. 자세한 이유는 [Claude Code 연동](/wiki/claude-code)에.

## "런타임 준비 중"이 오래 걸려요

첫 실행에만 어댑터를 자동 설치합니다 (npm, 고정 버전 — 수 분). 그 뒤로는 바로 붙습니다. 상태는 설정 → ocul-pm → 연동에서 확인할 수 있습니다.

## 앱 안 Claude Code 가 로그인이 안 된대요

앱에는 로그인 화면이 없습니다 — 어댑터가 인증 흐름을 제공하지 않아서입니다. 터미널에서 `claude` 를 실행해 한 번 로그인하면, 앱이 그 자격을 그대로 씁니다.

## 승인을 기다리는 줄 몰랐어요

에이전트가 승인 대기로 멈추면 **사이드바 Claude Code 줄에 깜빡이는 배지**가 붙습니다 (v2.11). 다른 화면에 있어도 보입니다. 승인 카드에는 실행될 명령·바뀔 내용이 그대로 실려 있으니 읽고 누르면 됩니다.

## 사용량이 걱정돼요

Claude Code 화면 툴바의 계기가 **오늘 · 주간 · 모델별** 사용률을 보여 줍니다. 누르면 초기화 시각까지 나오고, `/usage` 를 입력해도 같은 위젯이 열립니다. 이 조회는 토큰을 쓰지 않습니다.

## 업데이트했더니 하던 대화가 끊겼어요

업데이트 재시작은 앱과 함께 어댑터 프로세스도 새로 띄웁니다. **대화 자체는 디스크에 있어 그대로 돌아오지만**, 재시작 순간에 흐르고 있던 답변 하나는 잃습니다. 그래서 앱은 답변이 도는 동안에는 업데이트 재시작을 미룹니다.

## Claude Code 프로세스가 죽었대요

드물게 어댑터가 종료되면 배너가 뜹니다 (v2.11). 「다시 연결」을 누르면 어댑터를 다시 띄우고 보던 대화를 그대로 되살립니다.

## 코드 검색·코드 맵이 처음에 느려요

처음 한 번은 로컬 임베딩 모델을 내려받고 프로젝트를 인덱싱합니다. 이후에는 변경분만 갱신해서 빠릅니다. 전부 로컬 계산이라 코드는 밖으로 나가지 않습니다.

## 새 대화가 지난 대화 목록에 없어요

한 마디도 하지 않은 새 대화는 목록에 실리지 않습니다 — 첫 마디를 보내는 순간 진짜 세션이 만들어지고 목록에 나타납니다.

## macOS 가 파일·다른 앱 데이터 접근 권한을 물어봐요

정상입니다. 두 관문을 구분하면 이해가 쉽습니다.

- **공증(notarization)** 은 "이 앱을 **실행**해도 되는가"를 묻습니다. Ocul-PM 은 Apple Developer ID 로 서명하고 공증까지 마친 빌드라 여기는 그냥 통과합니다.
- **권한 프롬프트**는 "이 앱이 **저 데이터**를 읽어도 되는가"를 묻는 별개 관문입니다. 공증과 무관하고, 공증했다고 사라지지 않습니다.

물어보는 경우는 크게 둘입니다.

**프로젝트가 데스크탑·문서·다운로드 폴더 안에 있을 때.** macOS 가 보호하는 자리라 그 안의 파일을 읽으려면 한 번 승인이 필요합니다.

**내장 터미널에서 무언가를 돌렸을 때.** 이쪽이 뜻밖일 수 있습니다 — 터미널에서 실행한 명령이나 그 안에서 도는 에이전트(Claude Code·Codex)가 파일을 읽으면, macOS 는 그 접근을 **명령이 아니라 명령을 띄운 앱**에 귀속시킵니다. 그래서 `find ~/Library` 한 줄이 「'Ocul-PM.app'이(가) 다른 앱의 데이터에 접근하려고 합니다」를 띄웁니다. 터미널을 품은 앱(VS Code·iTerm 등)은 모두 같습니다.

**업데이트한 뒤 다시 물어봤다면** 서명이 바뀐 버전에서 한 번 그럽니다. macOS 는 승인 기록을 앱의 코드 서명에 묶어 두기 때문에, 서명 주체가 바뀌면 이전 승인이 무효가 됩니다. 같은 이유로 키체인(API 키)도 한 번 물어봅니다 — "항상 허용"을 누르면 끝입니다.

**앱이 먼저 묻지는 않습니다.** 설정 → ocul-pm → 연동의 Claude Desktop 칸은 상태를 보려면 Claude Desktop 의 앱 데이터를 읽어야 해서, **[Desktop 확인] 을 누를 때만** 조회합니다. 누르지 않으면 그 폴더를 건드리지 않습니다.

승인한 내용은 시스템 설정 → 개인정보 보호 및 보안에서 언제든 되돌릴 수 있습니다.
