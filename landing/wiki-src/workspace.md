## 창 하나 = 프로젝트 하나

4.0 부터 창 하나가 프로젝트 하나입니다. 3.x 의 크롬식 탭 · 떼어내기 · 메뉴바 트레이는 걷었고, 프로젝트 사이는 OS 의 창 전환(⌘` · Mission Control)으로 오갑니다.

| 키 | 동작 |
|---|---|
| `⌘O` | 최근 프로젝트 — 쳐서 거르고, 고르면 그 프로젝트의 창이 열리고, 이미 열려 있으면 그 창이 앞으로 옵니다 |
| `⇧⌘N` | 새 창 — 프로젝트가 없는 **시작 창** |
| `⌘W` | 창 닫기 — 터미널에 세션이 여럿이면 고른 세션부터 |
| `⌥Tab` | 최근 창으로 — 톡 누르면 직전 창, 누르고 있으면 최근 순 목록 (Windows · Linux 는 Ctrl+백틱) |
| `⌥⌘1` ~ `⌥⌘9` | 최근 순 프로젝트 창으로 바로 — 지금 창에는 번호가 없습니다 (Windows · Linux 는 `Alt+1` ~ `Alt+9`) |

- 시작 창에서 프로젝트를 고르면 **그 창이 곧 그 프로젝트**가 됩니다
- 창 제목이 프로젝트 이름이라 창 전환기에서 구분됩니다
- 윗줄의 프로젝트 이름(▾)을 누르면 프로젝트마다 가장 급한 상태 칩 하나가 섭니다 — 「기다림 N」 · 「확인 실패」 · 「새 소식」(그 창을 본 뒤 Claude 가 끝냈거나 멈춤) · 「실행 중 N」 · 「열림」(다른 창에 열려 있음). 기다리는 프로젝트가 맨 위, 다음이 확인 명령이 실패한 프로젝트라, 뒤에 있는 창의 Claude 가 어떤지 창을 열지 않고 압니다. 지금 창의 줄에는 「지금 창」, 다른 줄 끝에는 그 창의 `⌥⌘` 번호가 섭니다
- 프로젝트마다 화면 · 필터 상태를 따로 기억합니다
- **macOS 는 마지막 창을 닫아도 앱이 살아 있고**, 독 아이콘을 누르면 다시 엽니다. Windows · Linux 는 마지막 창을 닫으면 종료합니다
- 업데이트로 재시작하면 창마다 열려 있던 프로젝트가 그대로 돌아옵니다

:::note
관측(일지 · 변경 감시)은 앱이 살아 있는 동안 계속됩니다. 창을 다 닫아도 macOS 에서는 앱이 남아 있으니 감시가 이어집니다.
:::

## 파일 여는 법 — 외부 편집기

앱 안 편집기는 2026-10-28 에 걷었습니다(터미널은 10-29 에 작게 돌아왔습니다). 변경 · 터미널 · 작업 일지에서 파일을 열면 설정 → 앱의 **파일 열기**가 고른 편집기로 넘깁니다 — 자동(깔린 것을 찾습니다: VS Code, 다음 Cursor, 없으면 기본 앱) · VS Code · Cursor · 기본 앱 · 직접 입력. VS Code · Cursor 는 셸의 `PATH` 와 상관없이 그 파일 그 줄을 엽니다. 직접 입력은 셸 명령 템플릿이고, `%path` 가 절대 경로로, `%line` 이 줄 번호로 치환됩니다.

```
code -g "%path:%line"   VS Code 를 셸 명령으로
subl "%path"            Sublime Text
```

:::warn
macOS GUI 앱은 셸의 `PATH` 를 물려받지 않습니다. 직접 입력한 명령이 안 열린다면 절대 경로가 필요합니다 — 예: `/usr/local/bin/subl "%path"`.
:::
