화면이 *무엇을 보여주는가*는 [화면 둘러보기](/wiki/screens)에 있습니다. 이 문서는 그 화면들을 **어떻게 늘어놓고 굴리는가**입니다.

## 창 하나 = 프로젝트 하나

4.0 부터 창 하나가 프로젝트 하나입니다. 3.x 의 크롬식 탭 · 떼어내기 · 메뉴바 트레이는 걷었고, 프로젝트 사이는 OS 의 창 전환(⌘` · Mission Control)으로 오갑니다.

| 키 | 동작 |
|---|---|
| `⌘O` | 최근 프로젝트 — 고르면 그 프로젝트의 창이 열리고, 이미 열려 있으면 그 창이 앞으로 옵니다 |
| `⇧⌘N` | 새 창 — 프로젝트가 없는 **시작 창** |
| `⌘W` | 창 닫기 |
| `⌥⌘1` ~ `⌥⌘9` | 열린 프로젝트 창으로 바로 (Windows · Linux 는 `Alt+1` ~ `Alt+9`) |

- 시작 창에서 프로젝트를 고르면 **그 창이 곧 그 프로젝트**가 됩니다
- 창 제목이 프로젝트 이름이라 창 전환기에서 구분됩니다
- 윗줄의 프로젝트 이름(▾)을 누르면 프로젝트마다 「내 차례 · 새 소식 · 실행 중 N」 이 보여, 뒤에 있는 창의 Claude 가 끝났는지 창을 열지 않고 압니다
- 프로젝트마다 화면 · 필터 상태를 따로 기억합니다
- **macOS 는 마지막 창을 닫아도 앱이 살아 있고**, 독 아이콘을 누르면 다시 엽니다. Windows · Linux 는 마지막 창을 닫으면 종료합니다
- 업데이트로 재시작하면 창마다 열려 있던 프로젝트가 그대로 돌아옵니다

:::note
관측(일지 · 변경 감시)은 앱이 살아 있는 동안 계속됩니다. 창을 다 닫아도 macOS 에서는 앱이 남아 있으니 감시가 이어집니다.
:::

## 파일 여는 법 — 외부 편집기

앱 안 편집기와 터미널은 2026-10-28 에 걷었습니다. 변경 화면 · 일지 상세의 「열기」는 평소 쓰는 편집기로 넘깁니다. 명령 템플릿의 `%path` 가 절대 경로로, `%line` 이 줄 번호로 치환됩니다 — 기본값은 VS Code 입니다.

```
code "%path"          VS Code (기본값)
cursor "%path"        Cursor
subl "%path"          Sublime Text
```

:::warn
macOS GUI 앱은 셸의 `PATH` 를 물려받지 않습니다. `code` 가 안 열린다면 절대 경로가 필요합니다 — 예: `/usr/local/bin/code "%path"`.
:::
