데이터와 파일 구조

마지막 수정 2026-08-16

이 페이지에서원칙 — 파일이 진실입니다`.oculpm/` 구조백업과 이동무엇이 어디에 있나밖으로 나가는 것

원칙 — 파일이 진실입니다

Ocul-PM 의 모든 기록은 프로젝트 안의 마크다운 파일입니다. 앱의 데이터베이스(SQLite)는 화면을 빠르게 그리기 위한 캐시일 뿐이고, 언제든 파일에서 다시 만들어집니다. 그래서:

  • 앱을 지워도 기록은 남습니다
  • 기록을 git 에 커밋해 팀과 나눌 수도 있습니다
  • 에디터로 직접 읽고 고칠 수 있습니다 (평범한 마크다운입니다)

.oculpm/ 구조

.oculpm/
├─ journal/      작업 일지 — 날짜/분류별 .md
│  └─ 20260816/
│     ├─ Features_to_add/
│     ├─ Bugs/
│     └─ …
├─ planner/      살아있는 계획 문서 .md
├─ discussion/   결정 전 토의 문서 .md
├─ agents/       에이전트 기록 규칙의 마스터 템플릿
└─ index/        앱이 관리하는 캐시 (직접 수정 금지)
주의

index/ 만은 앱이 관리합니다 — 직접 고치거나 지우지 마세요. 나머지는 전부 여러분의 파일입니다.

백업과 이동

폴더를 복사하면 끝입니다. .oculpm/ 를 통째로 다른 컴퓨터의 같은 프로젝트에 옮기면 앱이 읽어서 캐시를 다시 만듭니다. git 에 포함해 두는 것이 가장 간단한 백업입니다.

밖으로 나가는 것

여섯뿐이고 전부 여러분이 시작합니다: ① 직접 설정한 LLM API 호출, ② 새 버전 확인(업데이트 체크), ③ 앱 안 Claude Code·Codex 를 쓸 때의 그 프로바이더 통신 (여러분의 구독 자격으로), ④ 눌렀을 때의 GitHub 조회 — 패치노트·플러그인/스킬 번들·테마 파일, ⑤ 의미 검색을 처음 켤 때 huggingface.co 에서 받는 임베딩 모델 한 번 (모델이 내려오는 것이고 코드는 올라가지 않으며 그 뒤로는 전부 오프라인), ⑥ 켜야만 존재하는 Notion 연동 — 그 인증(OAuth) 교환만 oculpm.com 을 거치고, 문서 내용은 Notion 으로 직접 갑니다. 그 외 텔레메트리·분석·계정 서버는 없습니다.
