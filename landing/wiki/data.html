마지막 수정 2026-10-29

이 페이지에서원칙 — 파일이 진실입니다`.oculpm/` 구조백업과 이동무엇이 어디에 있나밖으로 나가는 것

원칙 — 파일이 진실입니다

Ocul 의 모든 기록은 프로젝트 안의 마크다운 파일입니다. 앱의 데이터베이스(SQLite)는 화면을 빠르게 그리기 위한 캐시일 뿐이고, 언제든 파일에서 다시 만들어집니다(설정 → 데이터 → 「처음부터 다시 만들기」). 그래서:

  • 앱을 지워도 기록은 남습니다
  • 기록을 git 에 커밋해 팀과 나눌 수도 있습니다
  • 에디터로 직접 읽고 고칠 수 있습니다 (평범한 마크다운입니다)

.oculpm/ 구조

.oculpm/
├─ journal/      작업 일지 — 날짜/분류별 .md
│  └─ 20260816/
│     ├─ Features_to_add/
│     ├─ Bugs/
│     └─ …
├─ planner/      살아있는 계획 문서 .md (완료 조건 · 확인 명령 · 판정 로그)
├─ agents/       에이전트 기록 규칙의 마스터와 일지 규격(journal-spec.md)
└─ index/        앱이 관리하는 캐시 (직접 수정 금지)

3.x 가 만든 discussion/ · rollups/ · automation/ 폴더는 4.0 의 앱이 더 읽지 않지만 지우지도 않습니다 — 여러분의 파일입니다.

주의

index/ 만은 앱이 관리합니다 — 직접 고치거나 지우지 마세요. 나머지는 전부 여러분의 파일입니다.

백업과 이동

폴더를 복사하면 끝입니다. .oculpm/ 를 통째로 다른 컴퓨터의 같은 프로젝트에 옮기면 앱이 읽어서 캐시를 다시 만듭니다. git 에 포함해 두는 것이 가장 간단한 백업입니다.

4.0 으로 올린 뒤 첫 실행에 3.x 의 코드 색인 · 임베딩 표를 지웁니다(한 설치본에서 DB 837MB 중 358MB). 지우기 전에 ocul-pm.db.bak-v42 사본을 남기고, 지운 자리는 설정 → 데이터 → 「정리해서 돌려받기」가 디스크에 돌려줍니다.

밖으로 나가는 것

둘뿐이고 둘 다 여러분이 시작합니다: ① 새 버전 확인(업데이트 체크 — 목적지는 앱 설정에 고정, 서명 검증), ② 여러분이 누른 링크(OS 의 기본 브라우저가 엽니다). 앱은 LLM 을 부르지 않고, 화면(웹뷰)은 바깥 호스트에 닿지 않으며, API 키를 받지 않습니다. 텔레메트리 · 분석 · 계정 서버는 없습니다. 전체 원장은 개인정보 페이지에.
