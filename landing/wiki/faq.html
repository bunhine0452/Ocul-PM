자주 묻는 질문

마지막 수정 2026-10-29

이 페이지에서이게 뭘 해주나요돈과 프라이버시git 과 팀개념이 헷갈려요쓰다 보면여기 없는 질문이라면

처음 며칠 동안 실제로 자주 나오는 질문들입니다. 개념이 헷갈리는 것과 겁나는 것을 먼저 풀었습니다.

이게 뭘 해주나요

한 줄로

AI 에이전트가 여러분의 코드에 무슨 짓을 했는지, 사람이 읽을 수 있는 기록으로 남깁니다.

커밋 메시지는 무엇이 바뀌었나만 말합니다. Ocul-PM 은 왜 그렇게 했고, 무엇을 시도했다 실패했고, 어떻게 확인했는지를 남기고, 앱은 그중 사람이 볼 것만 펼칩니다 — 판정 실패 · 증거 없는 일지 · 기록 없는 변경. 목표는 에이전트가 한 일을 3분 안에 믿고 다음을 결정하는 것입니다.

일지는 제가 써야 하나요?

아니요. 에이전트가 씁니다. 여러분은 읽기만 하면 됩니다.

프로젝트를 추가하면 루트에 AGENTS.md 라는 규칙 파일이 생기고, Claude Code·Cursor·Gemini CLI 같은 에이전트가 이 파일을 읽습니다. "작업 하나를 끝내면 일지를 남겨라" 가 그 규칙입니다. 여러분이 시킬 필요조차 없습니다.

팁

직접 쓰고 싶다면 쓸 수도 있습니다 — 그냥 마크다운 파일이니까요. 하지만 그게 목적인 앱은 아닙니다.

AI 를 대신 실행해 주는 앱인가요?

아닙니다. 에이전트는 평소처럼 여러분의 터미널에서 쓰고, 앱은 그 작업의 기록 · 증거 · 계획을 받아 둡니다. 앱을 켜 두기만 하면 터미널에서 한 작업이 잡힙니다. (앱 안에서 Claude Code 를 띄우던 화면은 2026-10-28 에 걷었습니다.)

돈과 프라이버시

돈이 드나요?

앱은 무료이고, 돈이 드는 기능이 없습니다. 4.0 의 앱은 LLM 을 부르지 않아 API 키를 받지도 않습니다 — 파일 변경을 관측하고 에이전트가 쓴 마크다운을 읽는 게 전부입니다. 비용은 여러분이 터미널에서 쓰는 에이전트의 구독 · 과금뿐입니다.

제 코드가 어디로 나가나요?

아무 데도 안 나갑니다. 앱 안에 LLM 클라이언트가 없고, 화면은 바깥 호스트에 닿지 않습니다. 기기를 떠나는 것은 여러분이 시작한 둘뿐입니다 — 새 버전 확인과, 여러분이 누른 링크(OS 브라우저가 엽니다). 계정 서버도 텔레메트리도 없습니다. (자세히)

인터넷 없이 되나요?

됩니다. 일지 · 계획 · 변경 diff 는 전부 로컬입니다. 업데이트 확인만 안 됩니다.

Windows / Linux 는요?

베타로 냅니다 — Windows 10 2004 이상 · 11(x64)과 Linux x64(AppImage · deb). 릴리스마다 CI 러너에서 설치와 실제 앱 E2E 를 통과한 OS 만 올라갑니다.

참고

.oculpm/ 기록은 그냥 마크다운이라 어느 OS 에서든 읽힙니다. 팀원이 앱을 안 깔아도 저장소에 커밋된 일지를 읽는 데는 문제가 없습니다.

git 과 팀

.oculpm/ 을 git 에 커밋해야 하나요?

네, 커밋하는 걸 권합니다 — 그리고 앱이 알아서 준비해 둡니다.

프로젝트를 추가하면 .gitignore 에 관리 블록이 하나 붙어서, 캐시성 파일만 제외합니다:

# oculpm:begin v1
.oculpm/index/
.oculpm/hooks/
.oculpm/.lock
.oculpm/.schema-version
.oculpm/oculpm.log
.oculpm.backup-*/
# oculpm:end

그래서 일지 · 계획 · 규칙은 커밋되고, 앱이 다시 만들 수 있는 것은 빠집니다. 여러분이 손댈 일이 없습니다.

팀원과 공유되나요?

커밋해서 push 하면 그대로 공유됩니다. 팀원은 앱이 없어도 GitHub 에서 마크다운으로 읽을 수 있고, 앱을 설치하면 그 기록이 화면에 그려집니다.

충돌나지 않나요?

일지는 파일 하나에 작업 하나고 이름에 시각이 들어가서(2337_fix_...md) 서로 겹칠 일이 거의 없습니다. 계획은 한 파일을 여럿이 고칠 수 있는데, 변경 로그가 덧붙이기 전용이라 충돌이 나도 양쪽 줄을 다 남기면 끝입니다. 병렬 세션은 /oculpm:next 가 항목을 [~] 로 먼저 선점해 같은 항목을 잡지 않습니다.

남의 저장소에 일지를 남기고 싶지 않으면요?

.gitignore 에 .oculpm/ 을 통째로 넣으면 로컬에만 쌓입니다. 앱 동작에는 아무 영향이 없습니다.

개념이 헷갈려요

「워크데이」가 뭔가요?

하루의 경계를 여러분이 정하는 것입니다. 기본은 자정이지만, 새벽까지 코딩하는 사람에게 자정 경계는 불편합니다 — 새벽 2시에 한 일이 "내일" 로 넘어가 버리니까요.

프로젝트의 .oculpm/config.toml 에서 day_starts_at = "03:00" 처럼 바꾸면, 새벽 3시 전의 작업은 전날 폴더에 쌓입니다.

「세션」이 뭔가요?

앱이 파일 변경을 지켜보다가 에이전트가 일하기 시작하면 열고, 한동안 조용하면 닫는 단위입니다. 대략 "한 번 앉아서 한 일" 에 해당하고 20260821-002 처럼 불립니다. 일지가 어느 세션의 산물인지 자동으로 묶입니다.

일지 · 계획 · 판정, 뭐가 다른가요?

시간축이 다릅니다:

언제무엇
계획지금완료 조건 · 확인 명령 · 항목. 항목이 진행되며 글리프가 바뀜. 큰 결정은 ## 결정 블록
작업 일지일이 끝난 후무엇을 왜 어떻게 했는지, 무엇을 돌려 확인했는지
판정확인 명령을 돌린 뒤`판정 ✓✗ <결과 끝 줄>` 한 줄. 에이전트의 말이 아니라 결과가 정합니다

3.x 의 「문제 해결」(논의) 화면은 4.0 에서 걷었습니다 — .oculpm/discussion/ 파일은 그대로 둡니다.

화면 언어와 기록 언어가 다를 수 있나요?

네. 화면 언어(설정 → 표시)는 앱의 글자이고, 일지의 언어는 그것을 쓰는 에이전트와 규칙 템플릿을 따릅니다. 영어 화면으로 쓰면서 기록은 한국어로 남는 것이 가능하고, 이미 기록된 문서는 바뀌지 않습니다.

쓰다 보면

일지가 안 쌓여요

가장 흔한 원인은 터미널에서 에이전트를 쓰는데 플러그인을 안 깐 경우입니다. AGENTS.md 규칙만으로는 모델이 긴 세션 끝에 기록을 잊을 수 있습니다. 플러그인을 설치하면 세션 종료 훅이 걸려 구조적으로 남습니다.

빠진 게 있는지는 오늘 화면의 「확인할 것」이 알려 줍니다 — 관측된 변경 중 어느 일지에도 안 적힌 파일과 일지 없이 끝난 대화를 짚습니다. (자세히)

일지를 고쳐도 되나요?

됩니다. 평범한 마크다운이고, 고치면 앱이 알아서 다시 읽습니다. 다만 에이전트에게는 기존 일지를 고치지 말라고 규칙이 걸려 있습니다 — 이력이 조용히 바뀌면 신뢰할 수 없게 되니까요. 에이전트는 새 일지를 쓰고 related 로 잇습니다.

일지가 너무 많아지면요?

오늘 화면은 하루 60건이어도 넘치지 않습니다 — 증거가 선 일은 계획별로 한 줄에 접히고, 볼 것만 펼칩니다. 작업 일지 화면은 날짜별로 묶이고, 일지 검색(/)과 필터(종류 · 증거 없음)가 있습니다. 그리고 일지는 지워도 됩니다 — 그냥 파일입니다.

앱을 지우면 기록은요?

남습니다. 기록은 전부 프로젝트 폴더 안의 마크다운이고, 앱의 데이터베이스는 화면을 빠르게 그리기 위한 캐시일 뿐입니다.

여러 프로젝트를 동시에 쓸 수 있나요?

됩니다 — 창 하나가 프로젝트 하나입니다. ⌘O 로 최근 프로젝트를 열고(이미 열려 있으면 그 창이 앞으로), ⇧⌘N 으로 새 창을 띄웁니다. (자세히)

에이전트를 여러 개 섞어 써도 되나요?

됩니다. 일지마다 누가 어느 모델로 했는지 함께 적힙니다. (자세히)

AGENTS.md 를 지워도 되나요?

지우면 에이전트가 기록 규칙을 못 봅니다 — 일지가 끊깁니다. 이미 여러분이 쓰던 AGENTS.md 가 있었다면 걱정 마세요, 앱은 <!-- oculpm:begin --> 블록만 소유하고 나머지는 건드리지 않습니다.

앱을 항상 켜 둬야 하나요?

파일 변경을 관측하려면 켜져 있어야 합니다. macOS 에서는 마지막 창을 닫아도 앱이 살아 있어 관측이 이어지고, 독을 누르면 창이 다시 열립니다.

참고

앱이 꺼져 있어도 에이전트는 일지를 씁니다 (규칙은 AGENTS.md 에 있으니까요). 앱이 놓치는 건 파일 변경 관측과 그에 딸린 변경 diff · 기록 없는 변경 짚기입니다.
