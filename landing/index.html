자주 묻는 질문

누구를 위한 앱인가요?

매일 AI 코딩 에이전트로 개발하고, 다음 날 새 대화에 어제 맥락을 다시 설명하는 게 귀찮은 사람입니다. Claude Code 가 작업을 끝내면 일지가 남고, 다음 대화는 그 일지와 남은 계획을 시작 컨텍스트로 이어받습니다 — 위 하루 한 왕복가 그것입니다. 어쩌다 한 번 쓰는 사람에게는 이 왕복이 필요 없을 수 있고, 그래도 괜찮습니다 — 앱은 무료이고 데이터는 프로젝트 폴더의 마크다운이라 언제든 그만둘 수 있습니다.

Ocul 은 무엇인가요?

AI 코딩 에이전트와 함께 일하는 개발자를 위한 로컬-우선 AI 프로젝트 매니저(AI PM)입니다. 에이전트가 한 일을 사람이 3분 안에 믿고 다음을 결정하게 하고, 에이전트는 어떤 일이든 판정부터 깔고 시작하게 합니다. 에이전트가 남긴 일지 · diff · 계획 가운데 사람이 볼 것만 펼치고, 판정은 에이전트의 말이 아니라 확인 명령의 결과 끝 줄로 읽습니다. 앱은 LLM 을 부르지 않습니다.

다음 세션은 지난 작업을 어떻게 이어받나요?

Claude Code 플러그인의 SessionStart 훅이 최근 계획의 완료 조건 · 확인 명령 · 마지막 판정 · 미완 항목과 마지막 작업 일지 3건을 시작 컨텍스트에 싣습니다 — 네트워크 없이, 프로젝트의 .oculpm/ 만 읽어서. 앱의 계획 화면에서는 [터미널에서 실행]이 앱 안 터미널의 새 세션에서 claude 가 다음 항목부터 잇게 하고, [끝까지 (/goal)]는 완료 조건 · 확인 명령을 Claude Code 의 /goal 로 넘깁니다.

「마지막 판정」은 무엇인가요?

계획의 확인 명령을 실제로 돌린 결과입니다. 에이전트가 그 결과를 plan-log 메모에 판정 ✓ 418 passed · 판정 ✗ 2 failed 처럼 한 줄로 남기면, 플러그인의 시작 훅과 앱의 계획 화면이 같은 규칙(^(판정|verdict) (✓|✗))으로 그 줄을 읽습니다. 계획 화면은 제목 바로 아래 완료 조건 · 확인 명령 · 마지막 판정을 두고, 판정이 실패면 오늘 화면 「확인할 것」 맨 위에 섭니다. 항목이 다 닫혀도 판정이 통과해야 끝입니다 — 「됐다」는 에이전트의 말이 아니라 결과 끝 줄이 정합니다.

무엇이 제 컴퓨터 밖으로 나가나요?

둘뿐입니다. ① 업데이트 확인 — 앱 시작과 수동 확인 시 GitHub 릴리스 파일 한 장. 목적지는 설정에 고정돼 있고 서명을 검증합니다. ② 여러분이 누른 링크 — 앱이 보내는 것이 아니라 OS 의 기본 브라우저가 엽니다. 4.0 의 앱은 LLM 을 부르지 않고(API 키를 받지도 않습니다), 화면(웹뷰)은 바깥 호스트에 닿지 않으며, 임베딩 모델도 내려받지 않습니다. 절대 안 나가는 것: 일지 · 계획 · .oculpm/ 파일 · 소스 코드. 사용 통계와 크래시 리포트는 수집하지 않습니다 — 분석 SDK 가 앱에 없습니다. 이 목록은 저장소의 테스트가 빌드에서 지키고, 전체 목록과 직접 세는 법은 개인정보 페이지에.

앱 없이 Claude Code 플러그인만으로도 쓸 수 있나요?

네. Claude Code 에서 /plugin marketplace add bunhine0452/Ocul-PM 후 /plugin install oculpm@oculpm 두 줄이면 훅 브리지·MCP 도구 8종·스킬 5종이 전 프로젝트에 구성됩니다. 일지와 계획은 .oculpm/ 마크다운으로 쌓이고, 앱은 나중에 설치해도 그 기록을 그대로 읽습니다.

Windows · Linux 에서도 쓸 수 있나요?

네, 베타로 제공합니다. Windows 는 10 2004(빌드 19041) 이상 · 11 의 x64 설치 파일(.exe), Linux 는 x64 AppImage 와 deb 입니다. Linux 는 glibc 2.35 이상(Ubuntu 22.04 · Debian 12 이후)과 libEGL · libGLESv2 가 필요하고, AppImage 는 FUSE 2 가 있어야 합니다. Windows 빌드는 코드 서명이 없어 처음 실행할 때 SmartScreen 이 「Windows의 PC 보호」 를 띄웁니다 — 「추가 정보 → 실행」 을 누르면 됩니다. Visual C++ 런타임이 없는 PC 에서는 설치 파일이 먼저 깔아 줍니다. Windows 설치본과 AppImage 는 앱 안에서 자동 업데이트되고, deb 는 새 .deb 로 업데이트합니다. 매 릴리스 CI 러너에서 설치와 실제 앱 E2E 를 통과한 빌드만 올라가며, 통과하지 못한 버전에는 그 OS 파일이 없습니다. 실제 PC 에서의 확인이 쌓이면 베타를 뗍니다.

Ocul-PM 과 Ocul 은 같은 앱인가요?

네. 4.1 부터 앱 안에 보이는 이름이 Ocul 입니다. 설치된 앱(Ocul-PM.app) · 내려받는 파일 · 데이터 폴더 · 플러그인 oculpm · 프로젝트의 .oculpm/ 은 이름이 그대로라, 업데이트는 같은 자리에 깔리고 기록은 그대로 이어집니다.

설치할 때 macOS 경고가 뜨나요?

v2.45.0 부터 뜨지 않습니다. Apple Developer ID 로 서명하고 공증(notarization)까지 마친 빌드라, .dmg 를 열어 Applications 로 끌어다 놓고 그냥 실행하면 됩니다. 그전 버전은 서명이 없어 macOS 가 「손상되었기 때문에 열 수 없습니다」로 막았고 — 실제 손상이 아니라 내려받은 파일에 붙는 격리 표시였습니다 — 터미널에서 xattr -dr com.apple.quarantine 을 직접 쳐야 했습니다.

하루에 일지가 60건이면 오늘 화면이 넘치지 않나요?

넘치지 않습니다. 4.0 의 원칙은 「예외만 보여 준다」입니다. 오늘 화면은 사람이 볼 것 — 판정 실패 · 명령 증거 없는 일지 · 어느 일지에도 없는 변경 · 막힌 항목 · 사람 몫 결정 · 플러그인 새 판 — 만 펼치고, 증거가 다 선 일은 계획별로 한 줄에 접습니다. 하루 3건 쓰는 사람과 60건 쓰는 사람이 모드 없이 같은 화면을 씁니다. 3.x 의 간단/전문 밀도 토글은 그래서 걷었습니다.

에이전트가 일지를 안 쓰고 끝나면 앱이 알아채나요?

네. 플러그인 훅이 대화가 끝날 때마다 판정하고, 코드를 고쳤는데 일지가 없으면 턴을 한 번 막아 기록하라고 말합니다(대화당 한 번). v2.43.0 부터 그 판정이 대화 단위입니다 — 예전에는 프로젝트 전체의 가장 최근 일지 시각 하나로 봤기 때문에, 터미널을 여러 개 띄우면 옆 대화의 일지가 내 누락을 가리고 반대로 옆 대화의 편집이 내 것으로 읽혔습니다. 이제 근거가 없으면 「모른다」고 말합니다 — 모름을 미기록으로 뭉뚱그리지 않습니다. 다만 여러 대화가 동시에 살아 있으면 게이트는 침묵합니다 — 누구의 편집인지 확정할 수 없을 때 엉뚱한 대화를 붙잡느니 말하지 않는 쪽을 골랐고, 그 경우에도 「모름」으로 원장에 남습니다. 앱 쪽에서는 오늘 화면이 일지 없이 끝난 대화와 어느 일지에도 없는 변경을 「확인할 것」으로 짚습니다.

일지에 확인 표시를 한 뒤 에이전트가 내용을 고치면 어떻게 되나요?

v3.2.0 부터 확인 표시는 확인한 그 본문의 지문과 함께 남습니다. 그 뒤 본문이 바뀌면 그 일지는 더 이상 확인된 것으로 세지 않고, 명령 증거가 없는 일지라면 오늘 화면 「확인할 것」에 다시 섭니다. 다시 읽고 확인함을 누르면 지금 내용에 다시 묶입니다. 3.2.0 이전에 확인해 둔 일지는 지문이 없으므로 그대로 인정합니다 — 소급해서 흔들지 않습니다. 지문은 .oculpm/ 의 일지 파일 머리말(verified_hash)에 적히므로 앱 없이도 읽을 수 있습니다.

앱이 AI 를 부르지 않는다면, 요약이나 보고서는 어떻게 만드나요?

터미널의 에이전트에게 시킵니다. 4.0 에서 앱 안 LLM(요약 · 스탠드업 · 주간 롤업 · 릴리스 노트 초안 · 계획 AI 갱신)을 전부 걷었습니다 — 가장 많이 쓰던 저장소에서도 주간 롤업이 0건이었습니다. 생각은 에이전트가 하고, 앱은 증거를 결정적으로 보여 줍니다. 에이전트는 MCP 도구 journal_search · journal_read 로 쌓인 일지를 찾아 읽을 수 있고, 앱은 에이전트에게 붙여 넣을 프롬프트(다음 항목 · until-done · 기록 요청)를 만들어 클립보드에 담습니다.

3.x 의 검색 · 논의 · 브랜치 · 스킬 화면은 어디 갔나요?

4.0 에서 걷었습니다. 앱은 오늘 · 작업 일지 · 계획 · 변경 · 설정 다섯 면만 남았습니다. 근거는 실측입니다 — 코드 의미 검색의 색인이 앱 DB 837MB 중 358MB 였고(에이전트는 자기 grep 이 있습니다), 논의 문서는 12개 프로젝트 합쳐 18건, 자동화는 한 번도 돌지 않았습니다. 일지 검색은 작업 일지 화면(/)이 맡고, 큰 결정은 계획의 ## 결정 블록으로, 스킬은 플러그인이 맡습니다. 여러분의 .oculpm/ 파일(논의 문서 포함)은 지우지 않습니다. 업데이트 뒤 첫 실행에 옛 색인 표를 지우며, 지우기 전에 ocul-pm.db.bak-v42 사본을 남깁니다. 전체 표는 저장소의 docs/PROMISE.md 에 있습니다.

인터넷이 끊기면 어떻게 되나요?

그대로 동작합니다. 4.0 의 앱은 화면을 그리는 데 네트워크가 필요 없습니다 — 일지 · 계획 · diff 는 전부 프로젝트 폴더와 로컬 캐시에서 읽고, 앱은 LLM 을 부르지 않습니다. 끊겨 있는 동안 실패하는 것은 업데이트 확인 하나뿐이고, 시작 때의 자동 확인은 조용히 넘어갑니다.

테마 색을 바꿀 수 있나요?

설정 → 표시에서 밝게 · 어둡게 · 시스템(OS 를 따름)을 고르고 글자 크기를 정합니다. 3.x 의 테마 파일 · 프리셋 다섯 벌 · 프로젝트별 테마는 4.0 에서 걷었습니다 — 저장해 둔 옛 테마 설정은 「시스템」 으로 읽습니다.

내가 쓴 일지와 AI 가 쓴 일지를 구분할 수 있나요?

네. 기록마다 출처 배지가 붙습니다 — 직접(앱에서 사람이 작성) · 에이전트(Claude Code 등이 기록 규칙대로) · MCP · 백필(git 이력에서 복원) 등이고, 3.x 의 자동 초안 · 스케줄 · 감시 · 들여옴 일지도 그 배지 그대로 읽힙니다. 새 필드를 만들지 않고 일지 파일에 이미 적혀 있는 세션 id 와 에이전트 id 에서 결정론적으로 읽습니다.

프로젝트를 여러 개 동시에 열 수 있나요?

네, 창을 여러 개 엽니다. 4.0 부터 창 하나가 프로젝트 하나입니다 — 3.x 의 크롬식 탭과 떼어내기는 걷었고, 프로젝트 사이는 OS 의 창 전환으로 오갑니다. ⌘O 로 최근 프로젝트를 열고(이미 열린 프로젝트면 그 창이 앞으로 옵니다), ⇧⌘N 은 새 시작 창, ⌘W 는 창 닫기, ⌥⌘1~9 는 목록을 열지 않고 열린 프로젝트 창으로 갑니다. 윗줄의 프로젝트 이름(▾)은 프로젝트마다 「내 차례 · 새 소식 · 실행 중 N」 을 보여 줍니다. 프로젝트마다 화면·필터 상태를 따로 기억하고, macOS 에서는 마지막 창을 닫아도 앱이 남아 독을 누르면 다시 열립니다.

같은 일을 여러 에이전트에게 시켜 보고 고를 수 있나요?

네. 앱 안 터미널의 「여럿에서」 에 프롬프트와 개수(2~4)를 넣으면, 지금 커밋에서 worktree 를 그만큼 만들어 각각 claude 를 띄웁니다. 터미널 위 띠가 레인마다 바뀐 파일 · 줄 수와 그 안의 Claude 가 쓴 일지 · 검증 명령의 끝 줄을 보여 주고, 명령으로 검증한 레인 가운데 바뀐 줄이 가장 적은 레인에 「추천」 이 붙습니다. 「이것으로」 는 그 레인의 변경을 원래 폴더에 커밋 전 변경으로 가져오고, 「모두 정리」 는 worktree 와 가지를 지웁니다. worktree 는 앱 데이터 폴더에 만들어 프로젝트 폴더를 어지럽히지 않습니다.

Claude 가 사람에게 물어야 할 때 앱에서 답할 수 있나요?

네. Claude Code 플러그인의 MCP 도구 ask_user 가 질문을 오늘 화면에 띄우고, 고르거나 쓴 답을 그대로 Claude 에게 돌려줍니다(25분 안). Claude 가 터미널에서 사람을 기다리면 — 앱 안 터미널이든 앱 밖 터미널이든 — 오늘 화면 맨 위에 「Claude 가 기다려요」 가 서고, 창이 뒤에 있으면 OS 알림이 옵니다.

어떤 AI 코딩 에이전트와 함께 쓸 수 있나요?

「지원」 한 마디에 약속 셋이 섞여 있어 등급으로 나눕니다. ① 규칙 호환 — 규칙 파일만 심고, 일지는 모델이 규칙을 지키는 만큼 남습니다: Gemini CLI · Cursor · GitHub Copilot · Windsurf · Cline · aider · Zed · Antigravity · pi (AGENTS.md 를 읽는 에이전트라면 무엇이든 이 등급). ② 구조화 기록 — 에이전트가 oculpm MCP 기록 도구를 부릅니다. ③ 세션 관측 — 훅으로 시작·종료를 받고 일지 없이 끝난 대화를 가려냅니다: Claude Code · Codex (각자의 플러그인으로, ② 포함). 에이전트는 여러분의 터미널에서 돌고, 앱 안에서 구동하던 등급은 2026-10-28 에 화면과 함께 걷었습니다. 등급별 근거와 실측 검증 시점은 위키의 등급표에 있습니다.

폰이나 태블릿에서도 쓸 수 있나요?

앱은 데스크톱 전용입니다. v2.18.0 에 베타로 넣었던 모바일 연동(Tailscale 사설망 안의 폰 브라우저)은 걷어냈습니다 — 표면이 컸는데 쓰임이 그에 못 미쳤습니다. v3.13.0 의 claude.ai 보드 스킬(/oculpm:board)도 2026-10-28 에 걷었습니다. 밖에서 진행을 보려면 .oculpm/planner/ 의 플랜 파일을 저장소와 함께 보세요 — 원본은 늘 그 마크다운입니다.

내 코드나 데이터가 외부로 나가나요?

아니요. 모든 데이터는 프로젝트의 .oculpm/ 폴더와 로컬 SQLite 에 머뭅니다. 앱은 LLM 을 부르지 않고 화면은 바깥 호스트에 닿지 않습니다. 기기를 떠나는 것은 사용자가 시작한 둘뿐입니다 — ① 새 버전 확인, ② 사용자가 누른 링크(OS 브라우저가 엽니다).

팀·회사 도입이나 제휴(파트너십)를 문의할 수 있나요?

네. Ocul 은 로컬-우선이라 팀에 도입해도 코드와 기록이 밖으로 나가지 않습니다. 기업(Enterprise) 도입, 팀 단위 도입, 제휴·파트너십 제안은 bunhine0452@gmail.com 으로 보내 주세요 — 만든 사람이 직접 읽고 답합니다.

영어(English)도 지원하나요?

네. 설정 → 표시에서 화면 언어를 한국어 · English 중에 고르면 화면 전체와 오류 메시지가 함께 바뀝니다. 에이전트가 쓰는 일지의 언어는 화면 언어와 별개이고, 이미 기록된 문서는 다시 쓰지 않습니다.

지금 다운로드할 수 있나요?

네. GitHub Releases 에서 무료로 받을 수 있습니다 — macOS(Apple Silicon)와, 베타인 Windows(x64) · Linux(x64, AppImage · deb)입니다. 한 번 설치하면 이후 버전은 앱 안에서 자동으로 업데이트됩니다(Linux deb 는 패키지 관리자로). Intel 맥 빌드는 아직 없습니다.

시작하는 데 필요한 것은, 없습니다.

가입도, 설정도, 비용도 없습니다. 내려받으면 그게 전부입니다.
