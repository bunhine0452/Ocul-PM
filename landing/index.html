01 · 기록장

기록은 공짜여야 합니다.

에이전트가 일을 마치는 순간, 일지는 이미 쓰여 있습니다. 무엇을 왜 고쳤는지, 어느 에이전트가 어느 모델로 했는지 — 버그·기능·리팩토링·에러·잡일로 분류되어, 사람이 읽는 마크다운으로.

  • Today 브리프 — 아침에 열면 어제가 정리되어 있고, 스탠드업은 복사 버튼 하나
  • 기록이 산출물로 — PR 본문 · 주간 보고 · AI 회고, 전부 버튼 하나
  • 플래너 · 토의 문서 — 계획은 에이전트가 진행을 갱신하는 살아있는 문서
02 · 검증대

믿지 마십시오. 보십시오.

에이전트가 만졌다는 파일 — 커밋하기 전에, 앱 안에서 로컬 diff 로 확인합니다. 일지와 나란히 붙여 놓고 "말한 것"과 "실제로 바뀐 것"을 봅니다.

  • 코드 맵 — 고치기 전에 "바꾸면 12개 파일에 영향"을 먼저 압니다
  • 검색 3모드 — 의미(로컬 임베딩) · 심볼(AST) · 텍스트(FTS5)
  • 전부 로컬 — 임베딩도 로컬 계산. 코드는 한 글자도 밖으로 나가지 않습니다

Changelog

매주 조금씩, 꾸준히.

이 앱은 자기 자신으로 개발됩니다 — 아래 이력 전부가 Ocul-PM 의 작업 일지에서 나왔습니다.

  • v2.13.3 — 스페이스 뒤 앞 음절이 다시 찍히던 것 · 「안녕」 뒤에 스페이스를 치면 「안녕 녕」이 되던 문제입니다. 스페이스로 조합이 확정되면 앱이 입력 버퍼를 비우는데, 입력기가 아직 그 글자를 붙들고 있으면 비워진 버퍼에 다시 올립니다 — 앱이 이걸 새로 친 글자로 착각해 흘렸습니다. 바로 앞 버전에서 고친 스페이스 문제와 증상은 닮았지만 원인이 정반대(그건 너무 일찍, 이건 너무 늦게)였습니다. 개발용 빌드는 진단 로그 때문에 느려 이 틈이 닫혀 있어 정식 빌드에서만 나타났습니다.
  • v2.13.2 — 한글을 치다 스페이스를 누르면 앞 글자가 반복되던 것 · 「안뜨」 뒤에 스페이스를 치면 「안뜨뜬」처럼 직전 글자가 남고 띄어쓰기는 사라지던 문제입니다. 천천히 치면 멀쩡하고 문장을 빠르게 쓸 때만 나타났습니다. 한글 입력기가 「글자를 고쳐 쓰라」고 알려주는 신호는 키를 누른 시점보다 최대 0.24초까지 늦게 오는데, 그 사이 먼저 나간 띄어쓰기를 뒤늦은 고쳐 쓰기가 지워버린 타이밍 경합이 원인이었습니다. 함께 「코드」 화면의 저장도 손봤습니다 — CRLF 줄바꿈 보존, 프로젝트 밖 파일이 열리던 바로가기 차단, ⌘S 한 번에 저장이 두 번 나가던 것.
  • v2.13.1 — 터미널에서 한글이 두 번 찍히던 것 · 터미널의 Claude Code 에 한글을 길게 쓰다 오타를 지우면 지운 글자가 화면에 남아 「차」가 「ㅊ차」로, 백스페이스를 두 번 누르면 「호」가 「하ㅎ호」로 불어났습니다. 한글 입력기에서 조합 중인 백스페이스는 글자를 지우는 키가 아니라 음절을 한 단계 되돌리는 입력기 동작인데, 앱이 이것을 「입력이 끝났다」로 잘못 읽어 조합 상태를 버린 것이 원인이었습니다. 짧은 셸 명령에서는 거의 드러나지 않고 한글 문장을 길게 칠 때 상시로 나타나던 증상입니다.
  • v2.13.0 — 새 「코드」 화면: 앱 안에서 코드를 바로 열어 보고 고칩니다 · 검색·코드맵이 가리키는 파일을 보려고 에디터로 나가던 왕복의 끝 — 파일 트리에서 열면 문법 하이라이트(12개 언어)와 함께 바로 편집되고 ⌘S 로 저장합니다. 검색 결과·코드 맵에는 「코드 화면에서 열기」 버튼이 생겨 해당 줄로 점프합니다. 에이전트가 같은 파일을 고치면: 저장 순간 디스크가 바뀌어 있으면 덮어쓰지 않고 배너로 선택(디스크 버전 / 내 버전)을 묻고, 열어 둔 파일이 밖에서 바뀌면 편집 전이면 조용히 최신화, 편집 중이면 배너. 저장 안 한 편집은 화면을 옮겨도 남고 트리에 초록 점으로 표시됩니다.
  • v2.12.0 — 변경 diff · 코드 맵 · 코드 검색, 셋 다 한 단계 위로 · 사진이 바뀌면 diff 가 깨진 문자 나열 대신 이전/현재 이미지를 나란히 보여줍니다 — 체커보드 밑판 위에 크기 변화와 함께 (다른 바이너리는 크기 카드). 거터엔 실제 파일 줄 번호와 +12 −4 요약. 코드 맵은 플로팅 엣지 + 방향 화살표(A → B: A 가 B 를 사용)로 관계선 스파게티를 걷어내고, 언어 색이 스며든 카드와 「허브」 태그로 다시 그렸습니다. 코드 검색은 파일별 그룹 · 매치 형광펜 · 에디터 해당 줄로 점프 · 최근 검색어 · 결과 더 보기까지 — 결과가 코드로 이어집니다.
  • v2.11.0 — 에이전트가 고치는 내용이 보인다, 블라인드 승인의 끝 · Claude Code 가 파일을 편집하면 그 변경(diff)이 도구 카드에 그대로 그려집니다 — 지운 줄은 빨강, 넣은 줄은 초록, 줄에는 +12 −3 규모. 승인 카드에는 실행될 명령·바뀔 내용이 카드 안에 실려 제목만 보고 허용을 누르던 일이 끝났습니다. 승인 대기는 사이드바 배지로 알리고, 한글 조합 중 Enter 가 문장을 전송하던 버그도 고쳤습니다. 입력창 자동 확장 · ↑/↓ 지시 되부르기 · 파일 드래그&드롭 · 턴 영수증("도구 7 · 파일 3 · 1분 12초") · 답변 복사 · 죽은 프로세스 감지와 「다시 연결」까지 — 대화면의 마찰을 한꺼번에 걷어냈습니다.
  • v2.10.3 — 더블클릭은 창 크기만, 그리고 빈 화면의 끝 · 창 위쪽 빈 곳을 더블클릭하면 창 크기 조절과 함께 새 탭이 하나씩 늘어나던 문제를 고쳤습니다 — 그 자리는 곧 타이틀바라 더블클릭은 창 크기만 조절해야 합니다(새 탭은 + · ⌘T). 프로젝트를 열기 전 시작 탭의 설정 → ocul-pm 으로 들어가면 창 전체가 하얗게 비어 재시작밖에 길이 없던 것도 고쳤습니다. 나아가 화면 한 조각에서 오류가 나도 그 조각에만 갇히고 그 자리에 「다시 시도」가 뜹니다 — 다른 탭과 탭 줄은 그대로 쓸 수 있어, 무엇이 잘못되든 앱을 다시 켜는 것으로 몰리지 않습니다.
  • v2.10.2 — 도크는 오른쪽에도, 분리 창은 끌어서 이동 · 자리 바꾸기 버튼이 아래 → 왼쪽 → 오른쪽 으로 한 바퀴 돕니다(세로 두 자리는 폭을 함께 기억). 떼어낸 터미널 창은 타이틀바가 없는 모양이라 창을 잡는 자리를 앱이 직접 내줘야 하는데 그게 빠져 있어 창을 아예 움직일 수 없었습니다 — 이제 탭 줄의 빈 곳을 끌면 따라옵니다. 그리고 macOS 창 분할 단축키(⌃⌥←→↑↓) 가 이 앱에서만 안 되던 문제: 그건 시스템 전역 키가 아니라 「창」 메뉴 안 「이동 및 크기 조절」 항목의 단축키인데, ⌘W 를 되찾으려 메뉴를 직접 구성하면서 어느 것이 창 메뉴인지 알려 주지 않아 그 항목이 아예 없었습니다.
지난 이력 더 보기
  • v2.10.1 — 어느 화면에서나 터미널 · 셸을 보려면 터미널 화면으로 들어가야 했고, 일지나 플래너를 보려면 다시 나와야 했습니다. 이제 ⌘J 로 지금 보고 있는 화면 위에 터미널이 열립니다. 붙이는 자리는 아래(가로로 넓게) 또는 왼쪽(세로로 길게) 중에 고르고, 경계를 끌어 크기를 맞춥니다. 창으로 떼어내도 셸은 끊기지 않고 스크롤백까지 따라옵니다. 설정 → 모양에서 터미널 글자 크기를 px 로 정하고 실제 글꼴 미리보기로 확인합니다. 함께: Claude Code 의 할 일 목록이 보이고 앱 안 Claude Code 가 작업 일지를 직접 씁니다, 사용 한도·인증 실패·모델 폴백이 대화에 기록으로 남습니다, 부팅 화면이 앱 아이콘이 그려지는 모션으로 바뀌었습니다.
  • v2.10.0 — Claude Code 를 앱 안에서 직접 구동 · 사이드바에 새 화면 Claude Code. 여기서 시키면 진짜 claude 가 앱 안에서 파일을 고치고 도구를 쓰고 승인을 구합니다(Agent Client Protocol). 도구 호출·권한 승인이 대화 안 카드로 오고, 상단바는 세션 탭 줄이 됩니다. Effort · 권한 모드를 한 트랙에서 고르고, 최상위 단계 울트라코드는 설정이 아니라 프롬프트 키워드입니다. 이미지 붙여넣기, 모델 전환 구분선, 위젯형 /usage 도 함께. CLI 자신의 화면에만 사는 기능(/remote-control 등)은 진짜 터미널 탭에서 claude 를 띄우는 터미널 탈출구로 처리합니다. 업데이트해도 대화가 안 끊기고, 기존 구독 로그인을 그대로 씁니다.
  • v2.9.0 — 창과 탭 · 한 창이 프로젝트 여러 개를 탭으로 뭅니다. 끌어서 순서를 바꾸고 창 밖으로 떼어내면 새 창이 됩니다. 프로젝트마다 화면·필터 상태를 따로 기억하고 터미널 세션은 프로젝트에 묶여 탭이 창을 옮겨도 끊기지 않습니다. ⌘T 새 탭(=시작 탭) · ⌘W 탭 닫기 · ⇧⌘N 새 창. 시작 화면은 등록된 프로젝트 전부를 한 격자로 다시 짰고, 프로젝트마다 색 8종·아이콘 10종을 고릅니다. 상단바는 이제 추적 중인 프로젝트 전부를 감지합니다 — 그동안 탭을 열지 않은 프로젝트는 일지를 남겨도 놓치고 있었습니다.
  • v2.8.5 — 영어 지원 · 설정에서 화면 언어를 고르면 12개 화면 전체가 영어로 바뀝니다. 화면 문구뿐 아니라 오류 메시지와 AI 가 쓰는 작업 일지·회고·플래너 항목, 새 프로젝트에 심기는 기록 규칙까지 함께 따라갑니다. 화면 언어와 AI 작성 언어는 따로 고를 수 있고 — 화면은 영어, 일지는 한국어가 가능합니다 — 이미 기록된 문서는 다시 쓰지 않습니다. ⌘K 팔레트는 양쪽 언어로 모두 찾힙니다.
  • v2.8.4 — Pretendard 서체 · 화면 전환 속도 · 본문 서체를 Pretendard(애플고딕을 모델로 한 한글 서체)로 바꾸고, 그동안 지정한 굵기대로 그려지지 않던 96군데를 바로잡았습니다. 서체 파일은 7개 2.7MB → 1개 2.0MB. 변경 diff 화면은 코드 색칠 데이터를 열 때만 불러오도록 바꿔 프로젝트 진입 직후 로드량이 절반 아래로(266KB→125KB), 첫 코드 인덱싱도 기록을 묶어 처리해 빨라졌습니다.
  • v2.8.3 — 터미널 붙여넣기 수정 · 내장 터미널에 붙여넣은 내용이 두 번 들어가던 문제를 고쳤습니다. 중복만이 아니라 두 번째 사본은 줄바꿈이 날것으로 전달돼 각 줄이 명령으로 실행될 수 있었습니다.

FAQ

자주 묻는 질문

앱 안에서 코드를 직접 보거나 수정할 수 있나요?

네. v2.13.0 의 코드 화면에서 프로젝트 파일을 트리로 탐색해 문법 하이라이트(12개 언어)와 함께 바로 열어 보고, 가볍게 고쳐 ⌘S 로 저장할 수 있습니다. 검색 결과와 코드 맵에서 해당 줄로 바로 점프합니다. 에이전트가 같은 파일을 고치면 저장 시 덮어쓰지 않고 어느 버전을 유지할지 묻는 배너가 뜨고, 저장하지 않은 편집은 화면을 옮겨도 남습니다. 자동완성이 필요한 무거운 편집은 「외부 에디터로 열기」가 커서 줄까지 넘겨 줍니다.

터미널을 다른 화면과 같이 볼 수 있나요?

네. v2.10.1 부터 ⌘J 로 어느 화면에서나 터미널 도크가 열립니다. 붙이는 자리는 아래(가로로 넓게)·왼쪽·오른쪽(세로로 길게) 셋 중에 고르고, 경계를 끌어 크기를 맞춥니다. 터미널만 담긴 별도 창으로 떼어낼 수도 있으며 셸은 끊기지 않고 스크롤백까지 따라옵니다. 글자 크기는 설정 → 모양에서 px 로 직접 정합니다.

Claude Code 를 앱 안에서 직접 쓸 수 있나요?

네. v2.10.0 부터 사이드바의 Claude Code 화면에서 진짜 claude 가 앱 안에서 에이전트로 구동됩니다(Agent Client Protocol). 파일 수정·명령 실행 같은 도구 호출과 권한 승인이 대화 안 카드로 오고, v2.11.0 부터는 편집 diff(지운 줄·넣은 줄)가 카드에 그대로 그려지고 승인 카드에도 실행될 명령·변경 내용이 실립니다. 사고 강도(Effort)와 권한 모드를 한 트랙에서 고르고, 턴이 끝나면 무엇을 얼마나 했는지 한 줄 영수증이 남습니다. 기존 구독 로그인을 그대로 쓰고 어댑터는 첫 실행에 자동 설치됩니다.

프로젝트를 여러 개 동시에 열 수 있나요?

네. v2.9.0 부터 한 창이 프로젝트 여러 개를 탭으로 뭅니다. 탭을 끌어 순서를 바꾸거나 창 밖으로 떼어내 새 창을 만들 수 있고, 프로젝트마다 화면·필터·사이드바 상태를 따로 기억합니다. 터미널 세션은 프로젝트에 묶여 있어 탭이 창을 옮겨 다녀도 끊기지 않습니다. ⌘T 새 탭, ⌘W 탭 닫기, ⇧⌘N 새 창입니다.

Ocul-PM 은 무엇인가요?

AI 코딩 에이전트와 함께 일하는 개발자를 위한 로컬-우선 AI 프로젝트 매니저(AI PM)입니다. 에이전트가 한 작업을 자동으로 기록·정리하고, 변경을 로컬 diff 로 검증합니다.

어떤 AI 코딩 에이전트와 함께 쓸 수 있나요?

Claude Code, Codex CLI, Gemini CLI, Antigravity, pi 는 별도 설정 없이 동작하고, Cursor, Windsurf, GitHub Copilot, aider, Cline, Zed 는 설정에서 규칙 파일을 켜면 됩니다. AGENTS.md 를 읽는 에이전트라면 무엇이든 함께 쓸 수 있어 특정 도구에 묶이지 않습니다.

기록만 남기나요? 산출물도 만들어 주나요?

쌓인 작업 일지로 스탠드업 텍스트, PR 본문, 주간 보고를 생성하고, 기간별 회고와 일지 .md 내보내기도 지원합니다. AI 를 설정하면 AI 가 다듬고, 설정이 없어도 기본 형식으로 항상 동작합니다.

내 코드나 데이터가 외부로 나가나요?

아니요. 모든 데이터는 프로젝트의 .oculpm/ 폴더와 로컬 SQLite 에 머뭅니다. 외부로 나가는 건 사용자가 직접 호출한 LLM API 와, 새 버전 확인을 위한 업데이트 체크뿐입니다.

앱 없이 Claude Code 플러그인만으로도 쓸 수 있나요?

네. Claude Code 에서 /plugin marketplace add bunhine0452/Ocul-PM 후 /plugin install oculpm@oculpm 두 줄이면 훅 브리지·MCP 도구 5종·스킬 5종이 전 프로젝트에 구성됩니다. 일지와 계획은 .oculpm/ 마크다운으로 쌓이고, 앱은 나중에 설치해도 그 기록을 그대로 읽습니다.

팀·회사 도입이나 제휴(파트너십)를 문의할 수 있나요?

네. Ocul-PM 은 로컬-우선이라 팀에 도입해도 코드와 기록이 밖으로 나가지 않습니다. 기업(Enterprise) 도입, 팀 단위 도입, 제휴·파트너십 제안은 bunhine0452@gmail.com 으로 보내 주세요 — 만든 사람이 직접 읽고 답합니다.

영어(English)도 지원하나요?

네. v2.8.5 부터 설정 → 모양에서 화면 언어를 한국어 · English 중에 고르면 12개 화면 전체와 오류 메시지가 함께 바뀝니다. AI 가 쓰는 작업 일지·회고·플래너 항목의 언어는 따로 지정할 수 있어 화면은 영어, 기록은 한국어로 남기는 것도 가능하고, 이미 기록된 문서는 다시 쓰지 않습니다.

지금 다운로드할 수 있나요?
