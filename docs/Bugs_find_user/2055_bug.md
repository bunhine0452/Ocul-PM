# 버그 수정 예시

[] 버그 수정 후 체크 표시 (필요하다면 사용자가 정의한 버그를 좀 더 구체적으로 정의 해도 괜찮음)

- 발생 원인: 버그가 발생한 원인을 AI가 분석 
- 해결 방법: 어떤 로직을 어떻게 변경하여 버그를 해결했는지, 단계별 구체적인 접근 방식을 작성
- 수정, 삭제, 생성된 파일들: 영향을 받은 모든 파일의 경로와 이름, 그리고 작업 유형(Update/Delete/Create)을 명시

[x] Changelog 에 차이점이 안보이는 버그
- 원인: `commit_changelog_entry` 가 `git diff HEAD` 만 사용해서 변경 파일을 모았기 때문에 **untracked(추적되지 않은 새 파일)** 가 통째로 누락되었음. `--numstat` 에도 안 잡히고 `diff_patch` 에도 안 잡혀서 결과적으로 DiffModal 이 "diff 본문이 비어있습니다." 로 떠 보였음.
- 수정한 방법:
  - `git.rs` 에 `list_untracked` 헬퍼 추가 (`git ls-files --others --exclude-standard -z`, gitignore 존중).
  - `commit_changelog_entry` 에서 `git diff` 결과에 없는 untracked 파일을 fs 로 읽어 `--- /dev/null` + `+++ b/path` + 전 라인 `+` 로 시작하는 단방향 패치를 합성. `MAX_DIFF_BYTES` 캡과 누적 통계(total_files/added) 도 같이 갱신.
- 수정한 파일들:
  - `src-tauri/src/git.rs` (list_untracked 추가)
  - `src-tauri/src/commands/changelog.rs` (untracked 합성 블록)

[x] Changelog 에 기록된 파일들이 계속 남아있는버그
- 원인: AiWorkbench 의 "오늘 변경사항" 패널은 `file_changes` 테이블 + `files` 인덱스 해시 비교로 만들어지는데, changelog 에 저장해도 양쪽 모두 정리되지 않아서 다음 Scan 에서 같은 파일들이 계속 다시 잡혔음. UI 의 로컬 상태도 저장 후 비워지지 않았음.
- 수정한 방법:
  - DB 에 `delete_file_changes_for_paths` / `refresh_file_hash` 추가.
  - `commit_changelog_entry` 끝에서 방금 기록한 경로들에 대해 (a) `file_changes` 감사 로그 삭제, (b) 현재 디스크 컨텐츠의 blake3 해시로 `files.hash` 갱신 → 다음 `detect_file_changes` 가 같은 변경을 재발견하지 않음.
  - 프론트엔드 `AiWorkbench.handleSaveToChangelog` 성공 분기에서 `setFileChanges([])` 로 즉시 비움.
- 수정한 파일들:
  - `src-tauri/src/db.rs` (delete_file_changes_for_paths, refresh_file_hash)
  - `src-tauri/src/commands/changelog.rs` (저장 후 cleanup)
  - `src/features/code/AiWorkbench.tsx`

[x] Changelog 에 Export를 실행하면 `tokio-sqlite: Error("Wrong number of parameters passed to query. Got 2, needed 3")` 라고 뜨는 버그
- 원인: `Db::list_changelog_entries` 의 SQL 빌더가 `since=None` 분기에서도 마지막에 `LIMIT ?3` 을 그대로 붙여놔서, 바인딩은 `[project_id, limit]` 2 개인데 자리표시자는 3 개가 되어 sqlite 가 에러를 던졌음. Export 가 `from=None` 으로 호출하기 때문에 정확히 이 경로를 밟음.
- 수정한 방법: `since` 유무에 따라 SQL 문자열과 자리표시자 번호를 분기해서 prepare. since 가 있을 때는 `?1 ?2 ?3`, 없을 때는 `?1 ?2` 로 정확히 일치시킴.
- 수정한 파일들:
  - `src-tauri/src/db.rs` (list_changelog_entries)

[x] 오늘의 활동, 오늘의 완료가 업데이트 안되는 버그
- 원인: 프론트(`TodayScreen`)에서 `new Date().setHours(0,0,0,0)` 로 **로컬(예: KST) 자정** 의 unix 초를 보냈는데, 백엔드 `daily_brief` 가 이걸 다시 `ts - ts.rem_euclid(86400)` 로 **UTC 자정** 에 재정렬해버렸음. KST 기준 오늘 09:00~23:59 사이에 만들어진 엔트리/완료가 윈도우 밖으로 밀려서 카운트가 0 으로 보였음.
- 수정한 방법: `daily_brief` 에서 `date_unix` 가 Some 일 때는 프론트의 로컬-자정 값을 그대로 day_start 로 사용. None 분기(fallback)만 서버 UTC 자정으로 스냅.
- 수정한 파일들:
  - `src-tauri/src/commands/overview.rs` (daily_brief)
