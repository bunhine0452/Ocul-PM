마스터 플랜의 D5 는 이 Phase 를 "Cursor 의 진짜 차별점" 이라고 적었다. 실제로
만들어 보니 어려운 곳은 모델을 부르는 자리가 아니라 **되돌리기가 정확한가**

## D6 — ACP 가 아니라 프로바이더 채팅으로 간다 {#d6-chat-not-acp}

**D5 의 전제를 정정한다.** 마스터 플랜은 "ACP(Claude Code · Codex)가 이미 붙어
있어 전송 경로는 있고" 라고 적었는데, 코드를 읽어 보니 그 경로는 이 일에 안 맞다.

`acp_prompt`(`commands/acp.rs:333`)가 요구하는 것:

- **살아 있는 어댑터 연결** — 없으면 `acp_not_running`.
- **세션**과 `TurnGuard` — 한 번에 한 턴이라, AI 패널에서 대화가 도는 동안
  ⌘K 는 `acp_session_busy` 로 거절된다.
- 무엇보다, ACP 에이전트는 **자기 도구로 디스크를 고친다**. 편집기에는 아직
  저장 안 한 버퍼가 있고, 둘이 같은 파일을 서로 다르게 들고 있게 된다.

⌘K 가 필요한 것은 정반대다: **"이 선택을 고쳐 텍스트로 돌려 달라."** 그건
`commands.chat`(`commands/llm.rs:57`)이 이미 하는 일이고 — 한 번 묻고 한 번
받고, 디스크를 안 건드리고, 사용자가 설정한 프로바이더·모델·**폴백 체인**을
그대로 탄다.

부수 효과 하나가 크다: **백엔드 커맨드가 하나도 안 늘었다.** 이 라운드에서
`bindings.ts` 재생성은 병렬 세션 때문에 막혀 있는데(`{#cap-semantic}` 이 그래서
`blocked` 다), Phase 5 는 그 위험을 아예 안 건드리고 끝났다.

`temperature: 0` 으로 부른다 — 같은 지시에 같은 답이 나와야 되돌리고 다시 해 볼
수 있다.

## D7 — 제안은 **먼저 적용하고** 나서 검토한다 {#d7-apply-then-review}

Cursor 는 유령 줄(phantom lines)로 diff 를 먼저 보여 준다. Monaco 에서 그러려면
view zone 으로 지워진 줄을 그려 넣어야 하는데, 그 위젯 층은 이 편집기가
`diffOriginal`(diff 편집기)로 이미 한 번 푼 문제고 **두 벌을 만들 이유가 없다.**

그래서 반대로 간다: 제안이 오면 **선택 범위를 그 자리에서 갈아 끼우고**, 받은
조각을 초록으로 칠하고, 위젯이 "받기 / 되돌리기" 를 묻는다.

- 되돌리기가 정확한 이유: 원문 문자열을 세션이 들고 있고, 되돌리기는
  `compose(diff, [false,…])` = **원문 그대로**를 다시 쓰는 것이다. 그 등식을
  `code_inline_edit.test.ts` 가 문다.
- ⌘Z 도 그대로 산다 — 편집 하나로 들어갔으므로 한 칸이다.
- 이미 이 앱의 관용구이기도 하다: 인라인 비교의 "청크 되돌리기" 가 같은 모양이다.

## D8 — 조각 승인은 **토글**이다 {#d8-hunk-toggles}

`{#agent-hunk}`. 조각마다 받기/버리기 버튼을 다는 대신, 조각이 칩이 되고 누르면
켜지고 꺼진다. 켜고 끌 때마다 본문이 **즉시 다시 계산**돼서, 무엇을 받는 중인지
버튼을 누르기 전에 본문에서 보인다.

계산은 순수 함수 둘이다.

```
toHunks(diff)              // del/add 가 이어지는 구간 = 한 조각 (ctx 가 끊는다)
compose(diff, accepted)    // 켠 조각은 added, 끈 조각은 removed → 본문 + 줄 범위
```

`compose` 가 **줄 범위(spans)까지** 내는 것이 요점이다. 편집기가 초록으로 칠할
자리를 화면에서 다시 세면 여기와 어긋나고, 그 어긋남은 "한 줄 밀린 하이라이트"
라는 아주 찾기 어려운 모양으로 나타난다.

조각이 하나면 토글 줄을 안 그린다 — 받기/버리기가 곧 그 조각이라 소음이다.

비교 자체는 `features/chat/lineDiff.ts` 의 `diffLines` 를 **그대로** 쓴다. ACP
편집 패널이 쓰던 것이고, diff 를 두 벌 만들면 같은 변경이 두 화면에서 다르게
보인다.

## 모델은 시켜도 펜스를 붙인다 {#fences}

`extractCode` 가 있는 이유다. "no markdown code fences" 라고 시켜도 붙는다.
그대로 끼워 넣으면 코드에 ` ``` ` 세 줄이 박히고, 그건 사용자가 손으로 지워야
하는 종류의 오염이다.

규칙에 기대지 않고 걷되 **조심스럽게** 걷는다:

- 응답 전체가 펜스 **하나**로 감싸였을 때만 안쪽을 쓴다.
- 펜스가 여러 개면 안 건드린다 — 마크다운 파일이나 문서 문자열을 고치는
  중이었다면 진짜 펜스를 지우는 것이 더 나쁘다.
- **들여쓰기는 안 건드린다.** 첫 줄의 공백이 곧 그 코드가 놓일 자리다.

끝 개행도 원문에 맞춘다(`matchTrailingNewline`) — 모델이 하나 더 붙이면 빈 줄이
늘고, 빼면 다음 줄이 붙어 올라온다.

## 귀속 — 절반은 됐고 절반은 막혔다 {#attribution}

플랜 `{#agent-attribution}` 의 질문: "⌘K 로 들어간 편집이 일지·`entry_diffs` 에
누가 고쳤는지 남는가."

조사한 결과는 셋이다.

**1. `entry_diffs` — 이미 된다.** 일지의 `files_touched[].path` 마다 그 시점의
diff 를 sidecar 로 잡아 둔다(`oculpm/entry_diffs.rs`). ⌘K 편집도 파일에 남으므로,
그 파일을 짚는 일지가 있으면 diff 는 자동으로 붙는다. **만들 것이 없다.**

**2. 일지의 `agent` — 만들었다.** 문제는 ⌘K 편집에는 **일지를 쓸 에이전트가
없다**는 것이다. 사용자가 이 앱 안에서 모델을 부른 것이라 MCP `journal_write` 를
탈 주체가 없다. 그래서 화면이 초안을 만든다:

- 파일별로 ⌘K 편집을 누적하고(몇 곳 · +N −M · 어느 모델), 상태줄에 칩으로 띄운다.
- 칩을 누르면 `oculpm_create_manual_entry` 로 초안이 간다 —
  `agent: { id: <provider>, version: <model> }` · `files_touched` ·
  **`verified_by_user: false`**.

마지막 필드가 이 설계의 정직함이다. 그 필드의 뜻이 정확히 이것이고("자동 초안은
`Some(false)` — 사용자가 UI 에서 검토 후 토글한다"), 앱이 관측한 사실을 남기되
**사람의 확인을 사칭하지 않는다.**

본문도 앱이 아는 것만 적는다 — 몇 곳, 몇 줄, 어느 모델. "무엇을 왜 고쳤는지" 는
빈칸으로 남겨 사람이 채우게 한다. 거기에 그럴싸한 문장을 지어내면 그 기록은
거짓이 되고, 이 제품은 기록이 참인지로 값이 정해진다.

본문 문구는 UI 사전이 아니라 `attribution.ts` 가 두 벌 든다 — 이건 화면 카피가
아니라 **디스크에 기록되는 내용**이고, 축도 UI 언어가 아니라 작성 언어
(`getContentLang()`)다. `discussionTemplates.ts` 와 같은 부류라 한글 게이트의
`DISK_CONTENT` 에 넣었다.

**3. 로컬 히스토리의 `HistorySource` — 막혔다.** 판마다 `user`/`agent` 를 적는
자리가 **이미 있다**(`oculpm/history.rs`). 그게 진짜 알맞은 그레인인데, 지금
⌘K 편집을 저장하면 `user` 로 적힌다 — 앱의 `code_write` 가 남긴 자기-쓰기
쪽지를 워처가 읽어 "사람이 저장했다" 로 판정하기 때문이다(`take_source`).
**저자를 잘못 적는다.**

고치려면 `code_write` 에 인자가 하나 늘어야 하고, 그러면 `cargo test` 가
`bindings.ts` 를 다시 만든다 — `{#cap-semantic}` 과 **같은 이유로 막혀 있다**
(병렬 세션이 그 파일에 미커밋 변경을 들고 있다).

→ 이 절반은 플랜에 남긴다. 해제 조건도 같다.

## 계약

`CodeEditorProps` 에 둘이 늘었다. 둘 다 이 파일의 기존 규약("실행은 부모가
한다")을 따른다 — 편집기는 자리를 잡고 결과를 앉히기만 하고, 프로바이더·모델·
폴백 체인·프로젝트 id 는 위쪽 사정이다.

| prop | 뜻 |
|---|---|
| `onInlineEdit` | 메시지를 받아 대체 텍스트를 돌려준다. **없으면 ⌘K 를 아예 안 단다.** |
| `onInlineEditAccepted` | 받았다 (+N −M). 귀속을 남기는 것은 부모의 일. |
