# 첫 사용자 관찰 — 30분 · 설치부터 첫 일지까지

> 이슈 0 · 원격측정 없음(설계) · 14일 방문자 4. 이 앱의 완성도를 판정할 **외부 기준이 없다.**
> 리뷰어는 코드를 보지만 사용자는 화면을 본다. 세 사람이 설치해서 첫 일지를 보기까지를 **지켜보는 것**이
> 지금 가진 유일한 외부 기준이고, 비용은 0 이다. 결과는 플랜 `polish-round-20261027` `{#observe-three-users}` 의 로그에.

## 누구

- 한국에서 **Claude Code 를 터미널에서 일상적으로 쓰는** 개발자. 이 앱을 처음 보는 사람.
- 세 명. 한 명은 혼자 쓰는 사람, 한 명은 팀에서 PR 리뷰를 받는 사람, 한 명은 Codex 나 Cursor 도 같이 쓰는 사람이면 좋다.
- 아는 사람이어도 된다. 다만 **설명하지 않는다** — 설명한 순간 그 사람은 관찰 대상이 아니라 공동 저자가 된다.

## 무엇을 보나 (약속 1~5, `docs/PROMISE.md`)

| 단계 | 시작 | 끝 | 약속 |
|---|---|---|---|
| A 설치 | 랜딩 첫 화면을 띄운다 | 앱이 열린다 | — |
| B 프로젝트 | 앱이 열렸다 | 평소 쓰는 프로젝트가 탭에 떴다 | — |
| C 플러그인 | 프로젝트가 떴다 | `/plugin` 두 줄이 끝났다 (안 하면 그것도 결과) | 1 |
| D 작업 | 터미널에서 평소 하던 일을 시킨다 | 에이전트가 끝났다 | 1 |
| E 첫 일지 | 에이전트가 끝났다 | 작업 일지 화면 또는 Today 「첫 기록」 카드에 그 일지가 보인다 | 2 · 4 |
| F diff | 일지가 보인다 | 일지 옆 diff 를 열어 봤다 | 3 |
| G 이어하기 | 새 대화를 연다 | 시작 컨텍스트에 어제 일지가 실린 것을 알아챈다 | 5 |

A~E 가 30분 안에 끝나는지가 첫 질문이다. F·G 는 시간이 남으면.

## 어떻게

1. **화면 녹화**를 켠다 (본인 동의). 관찰자는 뒤에 앉고 입을 다문다.
2. 각 단계의 **시작·끝 시각**을 적는다. 끝나지 않은 단계는 끝 칸에 「멈춤」.
3. 사람이 **멈추거나 되돌아가거나 말을 하는** 순간마다 한 줄: 시각 · 화면 · 그 사람이 한 말 그대로.
4. 20분을 넘긴 단계는 그 자리에서 **힌트 하나**를 준다 — 힌트를 준 것도 기록한다. 그 뒤에도 안 되면 다음 단계로 넘긴다.
5. 끝나면 질문 셋만: 「이게 무엇을 하는 앱이라고 이해했나」 · 「내일도 켜 둘 것 같은가, 왜」 · 「지우겠다면 왜」.

```
...

질문 셋
1. …  2. …  3. …
```

## 멈춤 지점 분류

| 분류 | 뜻 | 받는 사람 |
|---|---|---|
| **말** | 화면의 글자가 뜻을 전하지 못했다 | 문구 수정 — 그날 고친다 |
| **길** | 다음에 무엇을 눌러야 하는지 몰랐다 | 첫 실행·Today 카드 — 플랜 항목으로 |
| **고장** | 앱이 한 약속을 지키지 않았다 | 결함 — 재현 경로와 함께 플랜 항목으로, 패치 |
| **기대** | 앱이 약속하지 않은 것을 기대했다 | 약속 문서 「약속하지 않는 것」 에 적을지 판단 — 기능 추가 사유가 아니다 |

세 명 중 **둘 이상이 같은 지점**에서 멈추면 그 지점이 다음 마이너의 첫 항목이다. 한 명만 멈춘 지점은 적어 두고 네 번째 사람을 기다린다.

## 하지 않는 것

- 설문 · 평점 · NPS. 숫자 셋은 아무것도 말해 주지 않는다. 말과 멈춤만 적는다.
- 관찰 중 고치기. 고칠 것은 다 끝난 뒤.
- 「이 기능 어때요」 묻기. 그 사람이 쓰지 않은 기능의 의견은 데이터가 아니다.
