## 왜 이 실험인가

"AI 가 어제를 기억하게" 라는 자리는 claude-mem(9.57만★)이 갖고 있다. 기능 하나로는 남는 독점이
없었고(임대·우편함은 mcp_agent_mail, 파일 계획은 planning-with-files), 남는 것은 두 가지였다.

1. 일지(에이전트가 말한 것) · diff(실제로 바꾼 것) · 기록 안 된 변경 · 구역 임대를 **한 기록에서
   서로 대조할 수 있는 위치**
2. 4개월 동안 이 저장소에 쌓인 실제 데이터 — 남이 소급해서 만들 수 없다

도구를 만들기 전에 이 저장소의 성적표 한 장을 글로 먼저 올려 반응을 본다. "내 저장소로도
보고 싶다" 가 나오면 설치 없이 도는 도구로 만든다.

## 지표 정의

| 지표 | 정의 | 범위 |
|---|---|---|
| 검증 근거 | `done` 일지의 **검증 칸 안에** 실행한 명령(`cargo test`·`pnpm test`·`tsc`…)이나 결과(통과·exit 0)가 있다 | 일지 전 기간 |
| 스스로 미확인 | 검증 칸 안에 "미확인·육안 대기·확인 못…" 이 있다. 칸 밖(원인 설명)은 보지 않는다 | 일지 전 기간 |
| 확인 버튼 | `verified_by_user: true`. "버튼을 눌렀나" 일 뿐이라 대표 지표로 쓰지 않는다 | 일지 전 기간 |
| 작업 대화 | Claude Code 대화(서브에이전트 포함)에서 **성공한** Edit·Write·MultiEdit 가 `.oculpm/` 밖 파일에 1회 이상 | 대화 기록 보존 창(30일) |
| 일지 연결 | 일지의 `agent.session` = 대화 id, **또는** 그 대화의 `journal_write` 결과가 돌려준 저장 경로 | 〃 |
| 일지에 없는 편집 | 작업 대화가 고친 파일 중, 그 대화에 연결된 일지의 `files_touched` 에 없는 것. 도구가 버린 경로는 따로 센다 | 〃 |
| 다시 고친 버그 | bug 일지의 파일 중 하나를 7일(14일) 안의 feature·refactor 일지도 바꿨다. 일지 3%(23건) 이상에 나오는 공용 파일 45개는 겹침에서 뺀다 → 낮게 잡힌 값. 원인 증명이 아니다 | 일지 전 기간 |

## 판독 중 찾은 결함 (고침)

`journal_write` 가 `files_touched` 를 **문자열 배열**로 받으면 경고 없이 빈 목록으로 저장했다
(`mcp/tools/mod.rs` 의 `filter_map` — `f.get("path")?` 가 문자열 원소에서 None). 09-04 이후
호출 250번 중 4번, 경로 59개가 유실됐다. 파싱을 `mcp/tools/files_touched.rs` 로 옮기며 문자열은
`update` 로 받고, 그래도 못 읽은 원소는 응답 `warnings` 로 알리게 고쳤다.
