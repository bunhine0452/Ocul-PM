# Ocul-PM 이 약속하는 것

> 완성도는 결함이 없는 상태가 아니라, **무엇을 약속하는지가 적혀 있고 그 약속이 매번 지켜지는 상태**다.
> 이 문서가 그 약속이다. 랜딩·README 의 첫 화면은 이 문서와 어긋나면 안 되고, 어긋나면 이 문서가 아니라
> 그쪽을 고친다. 진행 상태는 여기 없다 — `.oculpm/planner/` 의 활성 계획.

## 한 문장 (동사로)

Ocul-PM 은 「일지 앱」이 아니다. **에이전트가 한 일을 사람이 3분 안에 믿고 다음을 결정하게 하고, 에이전트는 어떤 일이든 판정부터 깔고 시작하게 하는 것**이다. 일지·diff·계획은 그 믿음의 증거이고, 판정은 에이전트의 말이 아니라 확인 명령의 결과 끝 줄이다. (명사를 동사로 — Rieseberg, "How to be more ambitious", 2026-10-13.)

4.0(2026-10-29)에서 앱은 다섯 면만 남았다 — **오늘 · 작업 일지 · 계획 · 변경 · 설정**. 원칙은 하나다: **예외만 보여 준다.** 화면의 크기는 에이전트가 한 양이 아니라 사람이 볼 것에 비례한다. 하루 3건 쓰는 사람과 60건 쓰는 사람이 모드 없이 같은 화면을 쓴다.

## 약속 (10문장)

1. 프로젝트 폴더에 규칙 파일(`AGENTS.md`) 하나를 심으면, 터미널의 Claude Code 가 작업 하나를 끝낼 때마다 `.oculpm/journal/` 에 사람이 읽는 마크다운 일지를 남긴다.
2. 그 일지는 앱을 켜 두었을 때 몇 초 안에 작업 일지 화면과 오늘 화면에 뜬다.
3. 일지마다 그 시점의 변경 diff 가 붙고, 일지 상세와 변경 화면은 네트워크 없이 그 diff 를 줄 단위로 보여 준다.
4. 오늘 화면은 사람이 볼 것만 펼친다 — 판정 실패 · 명령 증거 없는 일지 · 어느 일지에도 없는 변경 · 막힌 항목 · 사람 몫 결정. 증거가 선 일은 한 줄로 접힌다.
5. 다음 날 새 대화를 열면 플러그인의 SessionStart 훅이 최근 계획의 완료 조건 · 확인 명령 · **마지막 판정** · 미완 항목과 마지막 일지 3건을 시작 컨텍스트에 싣는다 — 어제를 다시 설명하지 않는다.
6. 계획은 `.oculpm/planner/*.md` 마크다운이 원본이고, 에이전트가 `plan_update` 로 갱신하면 계획 화면이 따라 바뀐다. 확인 명령을 돌린 결과는 `판정 ✓|✗ <결과 끝 줄>` 한 줄로 남고, 시작 훅과 앱이 **같은 규칙**으로 읽는다.
7. 데이터는 전부 프로젝트의 `.oculpm/` 폴더와 로컬 SQLite 캐시에 있고, 서버도 계정도 없다. **앱은 LLM 을 부르지 않고, 웹뷰는 바깥 호스트에 닿지 않는다.** 기기를 떠나는 것은 사용자가 시작한 것(업데이트 확인 · 연 링크)뿐이며 그 목록은 `src-tauri/tests/egress_inventory.rs` 가 빌드에서 지킨다.
8. 앱이 없어도 `.oculpm/` 은 git 에서 그대로 읽히고, 앱을 지워도 기록은 남는다. 화면을 걷어도 그 화면이 보던 파일(예: `.oculpm/discussion/`)은 지우지 않는다.
9. 위 1~8 은 **macOS · 터미널 Claude Code + oculpm 플러그인** 경로에서 릴리스마다 사람이 확인한다.
10. 앱에는 위 다섯 면(과 프로젝트가 없을 때의 시작 창)만 있다. 새 화면은 범위 동결(`CLAUDE.md`)을 따른다 — 제안은 되지만, 만들려면 사용자의 go 와 걷을 표면이 함께 있어야 한다.

다른 에이전트(Codex · Cursor · Gemini CLI)는 1~4 가 규칙 파일만으로 동작한다(Codex 는 훅도 있다). Windows · Linux 는 CI 러너가 설치·기동을 확인한 판만 올라가는 **베타**다. 9 의 「사람이 확인」 은 macOS 만이다.

## 4.0 에서 걷은 것 — 근거는 실측

새로 짜지 않고 고쳤다. 파일 규격 · MCP · 3개 OS 워처 · 서명/업데이트/CI 가 60일 fix 211건의 대부분을 흡수한 자산이고, 걷을 것을 걷으면 남는 핵심은 작다 (계획 `v4-major-20261028`).

| 걷은 것 | 근거 |
|---|---|
| 코드 의미검색 · 색인 · 검색 화면 | 앱 DB 837MB 중 임베딩 232MB + 청크 126MB. 에이전트는 자기 grep 이 있다. 043 마이그레이션이 그 테이블을 지운다. 일지 검색은 작업 일지 화면이 맡는다 |
| 앱 안 LLM (요약 · AI 갱신 · 롤업 · 릴리스 노트 · API 키) | 가장 많이 쓰는 저장소의 주간 롤업 0건, 자동 초안·자동 화해 꺼짐. 생각은 에이전트가, 앱은 증거를 결정적으로 |
| 자동화 | `automation_runs` 0행 — 한 번도 안 돌았다 |
| 논의 화면 (리치 편집기) | 12개 프로젝트 합쳐 18건, 마지막 2026-09-21. 큰 결정은 계획의 `## 결정` 블록 |
| 스킬·규칙 화면 · 플러그인 번들 임포트 | Claude Code 설정 관리자에 가까웠다. 스킬은 플러그인이 맡는다 |
| 브랜치 화면 · 메뉴바 트레이 · 테마 프리셋 · 새 프로젝트 마법사 | 뷰어 등급 · macOS 27 회귀 · 밝게/어둡게/시스템이면 충분 · 시작은 에이전트의 `/oculpm:inception` |
| 밀도(간단/전문) 토글 · 크롬식 탭 · 떼어내기 | 모드는 설계 실패의 표시다. 창 하나 = 프로젝트 하나, 오가기는 OS 의 창 전환 |
| 대화 임포트 · 선언적 설정 · Claude Desktop 연결 | 기록 → 믿음 → 다음의 고리에 닿지 않는다 |

## 측정 목표 — 「최선을 다한다」가 아니라 숫자

구체적이고 어려운 목표가 「최선을 다하라」보다 낫다(Locke & Latham). 이 저장소(`docs/launch/agent-report-card.py`)로 잰다. 오늘 화면의 하루 한 줄(「바깥 심판 증거 M건 · %」)이 첫 줄을 매일 보여 준다.

| 지표 | 지금 | 목표 | 왜 이 숫자인가 |
|---|---|---|---|
| 검증 칸에 바깥 심판 증거가 있는 일지 | 83% (10-27) | **97%** | 나머지 3% 는 「못 돌렸다」고 적은 것이어야 한다 |
| 일지 없이 끝난 세션 (Stop 훅 판정 `missing`) | 측정 중 | **0** | 약속 1 그 자체다. 하나라도 있으면 규칙이 아니라 결함이다 |
| 커밋에 든 파일 중 어느 일지에도 없는 비율 | 28% (10-27) | **10%** | 오늘 화면 「기록 없는 변경」이 매일 짚는다 |
| 활성 계획 중 판정(`판정 ✓|✗`)이 한 번이라도 남은 계획 | 측정 시작 (4.0) | **전부, 첫 리프부터** | inception 의 첫 리프가 확인 명령을 만들고 빨강을 보이는 것이다. 판정 없는 계획은 「됐다」는 주장으로 닫힌다 |
| 버그 일지 중 7일 안에 같은 파일을 다시 고친 비율 | 47% (10-27) | **30%** | `/oculpm:redteam` 이 합류 전에 반례를 찾는 만큼만 내려간다 — 안 내려가면 그 스킬은 걷는다 |

목표를 못 맞춘 것은 실패가 아니라 데이터다 — 다음 리뷰에서 숫자를 다시 적는다. 목표를 낮추는 것은 사유를 적고 한다.

## Rieseberg 의 네 축 → Ocul-PM 의 자리

| 축 | 글이 말하는 것 | 기계가 지키는 자리 |
|---|---|---|
| 고도 | 할 일이 아니라 결과 — 「그다음 무엇이 일어나야 하나」. 모델이 혼자 피드백을 받을 통로 | 템플릿 v20 §1 「완료 조건은 결과로」 · `/oculpm:inception` 이 「그다음」을 두 번 묻고 피드백 통로를 계획에 넣는다 · `plan_create` 의 `done_when` |
| 깊이 | 스스로 심판하지 않는다 · 원재료에서 · 어휘가 아니라 도구 · 비합리적으로 어려운 숫자 목표 | 판정 형식 `판정 ✓|✗` + 「마지막 판정」(훅 · 계획 화면 · 오늘의 판정 실패) · inception 의 깊이 네 질문과 「빨간 판정 먼저」 · 템플릿 「어려운 숫자 목표는 정상이다」 |
| 범위 | 명사를 동사로 · 분야의 방법 · 역할극 금지 · 크루 | inception 「동사와 방법」 · `/oculpm:redteam`(방법만, 역할극 금지) · `/oculpm:next` 의 `[~]` 선점(병렬 세션이 같은 항목을 잡지 않는다) · 오늘 「지금 일하는 중」 |
| 자기 효능감 | 구체적이고 어려운 목표 · 실패해도 된다 | `/oculpm:next until-done`(판정이 통과할 때까지, 멈춤은 넷뿐) · 「못 닿아도 된다 — 어디까지 갔는지 숫자로」 · 실패도 error 일지로 |

**주지 않는 것.** 야망은 도구가 못 준다 — 완료 조건을 자동 생성하거나 판정을 대신 내리면 글이 경고하는 상태(모델이 스스로를 심판)가 된다. 모든 장치는 **묻고 짚되 막지 않는다**.

## 이 문서를 고치는 규칙

- 문장을 **더하려면** 그 문장을 지키는 장치(테스트·게이트·확인 절차)를 같은 PR 에 넣는다.
- 문장을 **빼는** 것은 언제든 된다 — 그게 범위를 좁혀 완성도를 올리는 일이다.
- 화면을 **더하는** 것은 범위 동결을 따른다 — 사용자의 go 와 그 대신 걷을 표면이 함께 있어야 한다.
