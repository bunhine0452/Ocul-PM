# 04 — 컨텍스트 경제학: 능력 매니페스트 · 회상 게이트 · 메모리 화면

> Phase 5 · 상위: [00-master-plan.md](00-master-plan.md)

## 0. 현재 상태 — 코드가 스스로 말하는 문제

`src/features/chat/aiContext.ts` 의 주석이 문제를 정확히 적어 두었습니다.

> 토큰 라운드 (2026-07-30): 이 블록은 **매 메시지마다** 재조립돼 system 으로 다시
> 올라간다(AiPanelScreenV2).

지금 AI 패널은 매 턴 다음을 조립해 system 으로 올립니다:

| 블록 | 함수 | 특성 |
|---|---|---|
| RAG 코드 스니펫 | `buildContextSystem` | 질문마다 달라짐 (정당) |
| git 상태 | `buildGitSystemContext` | 자주 바뀜 |
| 활성 플랜 + 항목 | `buildPlannerSystemContext` | **거의 안 바뀜** |
| 최근 일지 + AGENTS 규칙 다이제스트 | `buildOculpmSystemContext` / `digestRules` | **거의 안 바뀜** |

두 가지가 동시에 잘못돼 있습니다.

1. **프롬프트 캐시가 매 턴 깨집니다.** 거의 안 바뀌는 블록이 매 턴 재조립돼
   system 앞자리에 들어가므로, 한 글자만 달라져도 그 뒤 전부가 캐시 미스입니다.
2. **회상 신호와 무관하게 항상 들어갑니다.** "이 함수 이름 뭐가 좋을까" 같은
   턴에도 플랜 전체와 일지 3건과 규칙 2,500자가 실립니다.

`digestRules` 는 이 압력의 흔적입니다 — 규칙을 2,500자로 **잘라서** 넣느라
우선순위 알고리즘까지 만들었고, 그 과정에서 한 번은 §5 시크릿 금지 조항이
통째로 잘려 나갔던 이력이 주석에 남아 있습니다. *예산이 없어서 규칙을 훼손한
것*입니다.

Osaurus 의 답은 잘라 넣는 게 아니라 **안 넣는 것**입니다.

## 0.1 적용 범위 — 어느 표면인가

이 Phase 는 **AI 패널(`AiPanelScreenV2` — 프로바이더 채팅)** 하나만 대상으로 합니다.
우리가 system 을 조립하는 유일한 표면이기 때문입니다.

**Claude Code 구동면(`ClaudeCodeScreenV2` / ACP)에는 적용하지 않습니다.** 그쪽은
컨텍스트를 어댑터가 스스로 관리하고, 규칙·스킬 로딩은 Claude Code 자신의
메커니즘(`CLAUDE.md`·`.claude/rules`·`.claude/skills`)이 합니다. 우리가 매니페스트를
끼워 넣으면 두 시스템이 같은 일을 두 번 하게 됩니다.

ACP 쪽에서 이 Phase 가 닿는 유일한 지점은 **발동 원장**입니다 — 우리가 주입하는
대신 *관측만* 합니다([02](02-provenance.md) §4).

## 1. 능력 매니페스트 (Osaurus `capabilities_discover` / `capabilities_load`)

Osaurus 는 스킬 본문을 프롬프트에 싣지 않습니다. **이름·설명·키워드만** 매니페스트로
올리고, 모델이 필요하다고 판단하면 검색해서 본문을 끌어옵니다.

ocul-pm 번역:

```
system (동결 · 캐시 안정)
  ## 이 프로젝트에서 쓸 수 있는 것
  - 규칙 7개:  agents-md(항상) · rules/typescript(paths: **/*.ts) · …
  - 스킬 4개:  run-evals(평가 실행) · tdd-workflow(테스트 우선) · …
  - 활성 플랜 2개: osaurus-bench-round(0/48) · tab-reattach-regression(3/6)
  - 최근 일지: 2026-08-31 5건 (bug 2 · feature 2 · chore 1)
  필요하면 아래 도구로 본문을 꺼내세요.

tools
  context_discover(query)  → 매니페스트 검색 결과 (키워드 매칭)
  context_load(kind, id)   → 규칙/스킬/플랜/일지 본문 전문
```

`context_load` 는 새로 만드는 게 아니라 **이미 있는 MCP 도구를 패널에 노출**하는
것입니다 — `journal_search` · `journal_read` · `plan_status` 가 정확히 이 역할을
합니다(`oculpm/mcp/tools.rs`). 외부 에이전트에게는 이미 주고 있으면서 우리
패널에게는 안 주고 통째 주입하던 셈입니다.

**효과**
- `digestRules` 의 절단이 사라집니다. 규칙은 잘리지 않고, 필요할 때 **전문**이
  옵니다.
- `MAX_CTX_PLANS = 4` 상한도 사라집니다 — 목록은 싸고 본문만 비쌉니다.

### 1.1 세션 시작 시 동결

Osaurus: *"매니페스트는 채팅 시작 시 동결된다 (프롬프트 캐시 안정성). 중간에
추가한 스킬은 다음 채팅 매니페스트에 뜨지만 discovery 로는 즉시 도달 가능하다."*

이 규약을 그대로 씁니다.

- 매니페스트는 대화 시작 시 1회 조립하고 그 대화 동안 **바이트 동일**로 유지합니다.
- 대화 중 규칙·스킬·플랜이 바뀌어도 매니페스트는 안 바꿉니다 — `context_discover`
  가 항상 디스크를 보므로 즉시 도달은 가능합니다.
- 워처가 `.oculpm` 변경을 알려도 진행 중 대화의 system 은 재조립하지 않습니다.

이것만으로 AI 패널의 프롬프트 캐시 적중률이 회복됩니다.

### 1.2 결정적 경로 — 슬래시 주입

Osaurus 의 `/skill-name` 은 검색에 의존하지 않고 그 한 메시지에 본문을 통째로
넣습니다. ocul-pm 도 같게 합니다 (`acpSlash.ts` 가 이미 슬래시 파서를 들고 있음):

| 입력 | 동작 |
|---|---|
| `/rules` | AGENTS 마스터 **전문**을 이번 턴에만 주입 |
| `/plan <id>` | 그 플랜 전문 |
| `/journal <date>` | 그 날짜 일지 전부 |
| `/skill <name>` | 그 스킬 SKILL.md 전문 |

"모델이 규칙을 못 봤다" 는 의심이 들 때 사용자가 **확정적으로** 밀어 넣을 수 있는
경로가 있어야 합니다. 검색이 유일한 경로면 실패가 조용합니다.

### 1.3 검색 인덱스는 키워드만

Osaurus: *"능력 검색은 이름·키워드·설명을 색인한다 — 지시문 본문은 색인하지 않는다.
사용자가 실제로 말할 단어를 키워드에 넣어라(‘텍스트 처리’ 말고 ‘요약, tldr, 핵심’)."*

`context_discover` 도 같습니다. 그리고 스킬 생성 폼(`skillTemplate`)에 **키워드
필드를 추가**하고, 도움말에 위 문장을 그대로 씁니다. 지금 `SKILL.md` 시드는
`name` + `description` 만 있습니다.

## 2. 회상 게이트

Osaurus 는 매 턴 메모리를 넣지 않습니다. 신호가 있을 때만, **≤800 토큰**으로.

| 신호 | 꺼내는 것 |
|---|---|
| "지난주에 뭐 했지" · "어제" · 날짜 표현 | 에피소드 다이제스트 |
| "내가 뭐라고 했지" · "정확히" | 원문(트랜스크립트) 폴백 |
| 과거에 나온 사람·프로젝트·주제 언급 | 고정 사실 |
| 회상 신호 없는 일반 질문 | **아무것도 안 넣음** |

ocul-pm 의 유리한 점: **에피소드가 공짜**입니다. 일지가 이미 세션 단위 요약이고,
디스크가 SSOT 이며, 사람이 읽을 수 있게 구조화돼 있습니다. Osaurus 가 LLM 으로
증류해서 만드는 것을 우리는 이미 갖고 있습니다.

**게이트 구현** (`aiContext.ts` 에 순수 함수로):
```ts
export type RecallSignal = "episode" | "fact" | "verbatim" | "plan" | "none";
export function detectRecall(turn: string, lang: "ko" | "en"): RecallSignal
```
- 결정적 규칙 기반 (LLM 0). 한국어/영어 양쪽 신호어를 사전으로.
- 신호 없으면 일지·플랜 블록을 **아예 조립하지 않습니다.**
- 매니페스트는 항상 남습니다 — 목록은 싸고, 모델이 스스로 꺼낼 길을 잃으면 안 됩니다.
- 예산: 회상 블록 총합 **≤800 토큰**(문자 환산 상한으로 근사). 넘치면 관련도 순.

## 3. 관련도 감쇠

Osaurus 의 고정 사실은 **관련도 점수가 시간에 따라 감쇠**하고 **사용될 때 다시
날카로워집니다**. "쓰이지 않는 사실은 흐려진다."

ocul-pm 에 필요한 곳은 **회상 후보 랭킹**입니다. `035_context_recall.sql`:
```sql
CREATE TABLE recall_stats (
  project_id INTEGER NOT NULL,
  kind       TEXT NOT NULL,        -- journal | plan | rule | skill
  ref        TEXT NOT NULL,        -- 경로 또는 id
  score      REAL NOT NULL,        -- 0..1
  use_count  INTEGER NOT NULL DEFAULT 0,
  last_used  TEXT,
  PRIMARY KEY (project_id, kind, ref)
);
```
- 주입되면 `use_count += 1`, `score` 상승
- 워크데이 경계에서 지수 감쇠 (반감기 30일)
- **파생 캐시입니다.** 지우면 균등 점수로 되돌아가고 기능은 유지됩니다 —
  SSOT 원칙 불변.

## 4. 메모리 관리 화면

Osaurus 의 `Management → Memory` 는 ocul-pm 에 **없는** UI 입니다. 우리는 데이터는
전부 갖고 있는데 그것이 컨텍스트에 어떻게 쓰이는지 볼 창이 없습니다.

설정 → **컨텍스트** 탭 (신설):

| 섹션 | 내용 | 동작 |
|---|---|---|
| 항상 가는 것 | 사용자 지시(override) 목록 | 추가·편집·삭제 |
| 매니페스트 미리보기 | 이번 대화가 받는 매니페스트 원문 | 복사 |
| 회상 후보 | `recall_stats` 상위 20 — 관련도 바 + 사용 횟수 | "잊기"(행 삭제) |
| 예산 | 이번 대화 회상 사용량 `312 / 800` | |
| 위험 구역 | 회상 통계 전체 초기화 | `useConfirm()` |

**"항상 가는 것"** 은 Osaurus 의 identity override 입니다 — *"항상 한국어로",
"탭 말고 스페이스"* 같은, 모델이 절대 잊으면 안 되는 짧은 사실. 지금 ocul-pm 은
`systemPrompt` 설정 하나로 이걸 대신하는데, 한 덩어리 텍스트라 개별 관리가
안 됩니다. 줄 단위 목록으로 승격합니다.

**프로젝트 지시문**: Osaurus 의 Projects 는 프로젝트마다 instructions 를 갖고
자동 저장됩니다. ocul-pm 도 프로젝트별 "항상 가는 것" 을 둡니다 (전역과 병합,
프로젝트가 우선). AGENTS.md 와 다른 층입니다 — AGENTS.md 는 **기록 규칙**(외부
에이전트가 읽음), 이건 **사용자 선호**(우리 패널이 읽음).

## 5. 마이그레이션 위험

`digestRules` 를 제거하면 규칙이 더 이상 자동으로 안 들어갑니다. 모델이
`context_load` 를 안 부르면 규칙 없이 답할 수 있습니다.

완화:
- 매니페스트에 **규칙 요약 3줄**(무엇을 금지하는지)은 항상 남깁니다 — 시크릿
  금지 같은 안전 조항은 온디맨드로 미룰 수 없습니다.
- `/rules` 결정적 경로(§1.2)
- 발동 원장([02](02-provenance.md) §4)이 "규칙이 실제로 걸렸는가" 를 계속 관측합니다
- 릴리스 전 회귀 게이트 — 막연한 "10문항 A/B" 가 아니라 **고정 픽스처**로:
  `src/__tests__/fixtures/rules-compliance/` 에 질문 12개와 각 질문이 반드시
  참조해야 할 규칙 절을 적어 두고, 구/신 경로가 조립한 **컨텍스트 문자열**을
  비교합니다 (LLM 호출 없음 — 결정적). 신 경로가 `context_load` 를 부르지 않아
  규칙 절이 빠지면 그 케이스가 실패합니다. 모델 응답 품질이 아니라 **규칙이
  도달 가능한가**를 재는 테스트입니다.

## 6. 테스트

| 대상 | 방식 |
|---|---|
| 매니페스트 동결 | 대화 중 규칙 파일 변경 → system 바이트 불변 |
| 회상 게이트 | 한/영 신호 문장 × 4종 + 무신호 → 기대 `RecallSignal` 테이블 |
| 무신호 턴 | 일지·플랜 블록 길이 0 |
| 예산 | 회상 후보 과다 → 800토큰 근사 상한 준수 + 관련도 순 |
| 슬래시 주입 | `/rules` → AGENTS 마스터 **전문**(절단 마커 없음) |
| 감쇠 | 시각 주입 60일 → 점수 반감 2회, 사용 시 회복 |
| 통계 삭제 안전 | `recall_stats` 비우고도 전 경로 정상 |
