# 02 — 출처와 상태를 보이게 (Provenance)

> Phase 3 · 상위: [00-master-plan.md](00-master-plan.md)

## 0. 문제

ocul-pm 의 기록은 이미 여러 출처에서 옵니다 — 사람이 직접, Claude Code 가 규칙을
따라, MCP 도구로, 자동 화해가, git 백필이. 그리고 Phase 1·2 가 스케줄·워처
자동화를 더합니다.

**그런데 화면에서 구분되지 않습니다.** 일지 카드도 ACP 세션 줄도 "누가 이걸
만들었는지" 를 말하지 않습니다. 자동화를 켠 다음 이 구멍은 결함이 됩니다:
사용자가 자기가 쓴 일지와 기계가 쓴 일지를 못 가립니다.

Osaurus 는 이걸 사이드바에서 해결합니다 — 각 대화에 **소스 배지**(Chat / Plugin /
API / Channel / Schedule / Watcher / Self-scheduled / Imported)를 달고, 상단에
**배지 필터 레일**을 둡니다. 소스가 하나뿐이면 레일은 스스로 숨습니다.

## 1. 소스 분류 (ocul-pm)

`SessionId` 변형([01](01-automation.md) §0.2)에서 결정론적으로 파생합니다.
**새 필드를 만들지 않습니다** — 이미 있는 사실을 읽습니다.

| 배지 | 출처 | 파생 |
|---|---|---|
| 직접 | 사람이 앱에서 작성 | `SessionId::Manual` |
| 에이전트 | Claude Code 등이 AGENTS.md 규칙대로 작성 | 워처 세션 + `agent.id ≠ auto:*` |
| 자동 초안 | 세션 종료·정착 트리거의 LLM 초안 | `agent.id = auto:*` |
| 스케줄 | 시간 자동화 | `SessionId::Schedule` |
| 감시 | 워처 자동화 | `SessionId::Automation` |
| MCP | MCP 도구 호출 | `SessionId::Mcp` |
| 백필 | git 이력에서 복원 | `SessionId::GitBackfill` |
| 들여옴 | 외부 대화 임포트 (Phase 7) | 임포트 마커 |

배지는 **한 글자 아이콘 + 툴팁**이 기본이고, 목록 폭이 넓으면 라벨을 폅니다
(polish-round 의 `.chip` 프리미티브 재사용 — 새 컴포넌트를 만들지 않습니다).

## 2. 붙는 자리

| 화면 | 자리 | 비고 |
|---|---|---|
| 일지(`features/oculpm`) | 타임라인 카드 우상단 | 날짜 스크러버와 겹치지 않게 |
| 오늘(`features/today`) | 활동 피드 행 | |
| ACP 세션 목록(`AcpSessionTabs`) | 세션 줄 | |
| 검색 결과 | 결과 행 | 출처로 좁히는 게 검색에서 특히 유용 |
| 회고 | 신호 기여 행 | "이 신호는 기계가 쓴 일지에서 왔다" |

**필터 레일**은 일지 화면과 ACP 세션 목록 두 곳에만 둡니다. 규칙은 Osaurus 와
동일: 현재 목록에 소스가 1종뿐이면 레일을 그리지 않습니다 (빈 필터는 소음).

> **구현 결과 (2026-09-01)** — 위 표의 다섯 자리 중 **셋에만** 붙였습니다
> (일지 카드·일지 상세·오늘 피드·회고). 나머지 둘을 비운 이유:
>
> - **검색 결과** — 검색 화면은 코드 검색(청크·심볼·정확)이라 일지 행이 없습니다.
>   일지의 화면 내 검색 결과는 그대로 일지 카드이고 이미 배지를 답니다.
> - **ACP 세션 목록** — ACP 대화는 전부 한 출처(앱에서 사람이 연 것)입니다. 모든
>   줄이 같은 말을 하는 배지는 라벨이 아니라 소음이고, 레일은 위의 자기 규칙에
>   의해 어차피 안 그려집니다. 그 자리에는 §3 의 상태와 인라인 Stop 이 들어갔습니다.

## 3. 활성 대화 행

Osaurus: 히스토리가 활성 대화를 **맨 위로 띄우고**, 행이 `Running…` 또는
`Needs your input` 을 말하며, **행 자체에 Stop** 이 있습니다 — 열지 않고 중단.

ocul-pm 의 `AcpSessionTabs` + `acpBusyBus` 에 적용합니다.

| 상태 | 표시 | 판정 |
|---|---|---|
| 진행 중 | `실행 중…` + 스피너 | `acpBusyBus` 가 busy |
| 입력 대기 | `입력을 기다립니다` (강조색) | 어댑터가 권한/질문 요청을 냄 |
| 유휴 | 상대 시각 | 그 외 |

- **정렬**: 활성 세션을 맨 위로. 단 `acpHistory.stabilizeHistory` 의 원장 규약을
  깨지 않습니다 — 활성은 정렬 키 **앞에 붙는 별도 버킷**이지, `updated_at` 을
  건드리는 게 아닙니다.
- **인라인 Stop**: 행의 액션 묶음에 붙는 `.iconbtn`. 자동화 실행 카드에도 같은
  컨트롤을 붙여 러너의 취소를 부릅니다([01](01-automation.md) §0.3).
  **우클릭 메뉴는 만들지 않았습니다** (2026-09-01) — 세션 줄은 이미 보이는 액션
  묶음(이름 바꾸기·삭제)을 갖고 있어 같은 동작으로 가는 숨은 두 번째 길은 표면만
  늘리고, 저장소에 공용 컨텍스트 메뉴 프리미티브도 없습니다.
- 자동화 실행 중일 때 설정 → 자동화 카드도 같은 `실행 중…` 을 표시합니다.

## 4. 발동 원장을 디버깅 도구로 재포지셔닝

`firing_ledger.rs` 는 이미 Claude Code transcript 에서 **규칙 주입**과 **스킬 발동**을
결정론적으로 관측합니다(LLM 0 · 네트워크 0 · 증분 스캔). 지금은 스킬 화면의
배지로만 쓰입니다.

Osaurus 는 같은 데이터를 **Insights** 로 부르고, 스케줄/워처 문서의 "결과가
이상하다" 항목에서 *"Insights 를 열어 어떤 능력이 로드되고 어떤 도구가 실제로
호출됐는지 보라"* 고 정식 절차로 지정합니다.

ocul-pm 도 같게 합니다.

1. **진단 탭(닥터)에 「발동」 섹션** — 최근 7일 규칙·스킬 발동 상위 목록 +
   "한 번도 안 걸린 규칙" 목록. 후자가 진짜 값입니다: *써 놓고 안 걸리는 규칙*이
   가장 흔한 실패입니다.
2. ~~**자동화 실행 상세에서 원장으로 점프**~~ — **폐기** (2026-09-01, 플래너
   `#d9-ledger-scope`). 원장이 읽는 것은 Claude Code transcript 뿐인데 자동화는
   `runner.rs` 가 배경 모델을 직접 부르므로 `sched-`/`auto-` 세션은 원장에 아예
   없습니다. 만들면 언제나 빈 화면으로 데려가는 문이 됩니다.
3. **문구** — 자동화 에디터와 진단 양쪽에서 §2.5([01](01-automation.md))의
   트러블슈팅 표를 같은 말로 씁니다. 「결과가 이상하다」는 2항의 정정에 따라
   *자동화는 규칙·스킬을 싣지 않으므로 지시문이 곧 전부이고, 먼저 볼 곳은 실행
   기록의 결말과 사유* 라고 말합니다 — 원장은 **에이전트가 쓴** 일지를 의심할
   때의 경로입니다.

## 5. 닥터 탭 자동화 섹션

polish-round 에서 진단 탭이 "닥터" 가 되었습니다(워처·락·ACP·키·마지막 색인
한 표). 여기에 행을 더합니다.

| 행 | 값 | 문제일 때 |
|---|---|---|
| 배경 모델 | `core_provider:core_model` 또는 **미설정** | 미설정이면 자동화 전부 정지 → 설정 딥링크 |
| 스케줄 | 활성 N개 · 다음 실행 시각 | 전역 스위치 off 면 명시 |
| 감시 자동화 | 활성 N개 · 티어 | |
| 오늘 자동 실행 | `사용 12 / 예산 20` | 예산 소진 시 경고 |
| 최근 실패 | 마지막 실패 run + 사유 | 클릭 → History |
