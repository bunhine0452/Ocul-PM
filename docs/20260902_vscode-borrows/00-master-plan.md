# VS Code 에서 가져오는 7가지 — 코드 화면 라운드 (설계 SSOT)

작성 2026-09-02 · 상태: 설계 완료 · 미착수
참조 체크아웃: `~/desktop/source_code_of_the_world/vscode` (Code-OSS, 읽기 전용 참고 자료)

## 왜

코드 화면은 이미 에디터를 넘어섰다 — LSP 일습(완성·진단·정의·이름 바꾸기·포맷·시그니처),
git 거터, 인라인 비교(HEAD·일지), 참조 패널, 아웃라인, 전역 검색·치환, 디버그, 분할,
닫은 탭 복원, 이미지·PDF·svg 미리보기.

없는 것은 **하루 종일 켜 두는 편집기의 위생**이다. VS Code 를 20년 쓰면서 아무도 의식하지
않는 것들 — 저장하면 공백이 정리되고, 저장을 잊어도 파일이 최신이고, 파일을 훑어도 탭이
안 쌓이고, 심볼로 바로 뛰고, 스크롤해도 지금 어느 함수인지 보이고, 문제가 한곳에 모이고,
실수해도 되돌릴 판이 남아 있는 것. 이 라운드는 그 7가지를 가져온다.

**VS Code 는 포크하지 않는다** (`docs/lsp/00-master-plan.md` 의 결정 — src/ 만 TS 8,572 파일,
Electron 42, 그리고 이 제품의 해자는 에디터가 아니라 에이전트 중립적 기록층이다). 가져오는
것은 코드가 아니라 **동작과 그 동작이 왜 그렇게 생겼는지**다. 각 문서는 근거가 된 VS Code
소스 경로를 적어 둔다.

## 이 앱에서만 다른 전제

세 가지가 VS Code 와 다르고, 설계가 그 차이를 따른다.

1. **파일을 사람만 고치지 않는다.** 에이전트가 같은 파일을 동시에 고친다. 그래서 저장은
   낙관적 잠금(blake3)이고, 워처가 외부 변경을 밀어 넣고, 자동 저장은 그 충돌 경로를
   반드시 지나가야 한다.
2. **diff 가 제품이다.** 일지·변경 diff·회고가 전부 diff 위에 산다. 그래서 "저장이 만드는
   노이즈"(후행 공백, 끝줄)는 다른 앱보다 비싸다.
3. **`.oculpm/` 이 SSOT 이고 SQLite 는 캐시다.** 새로 저장하는 것(로컬 히스토리)은 이
   규율을 따라야 한다 — 어디에 무엇을 쓰는지가 곧 설계다.

## 7가지 · 순서 · 비용

구현 순서는 **비용 오름차순**이다. 앞의 셋은 서로 독립이고 프런트만 건드린다.

| # | 이름 | 무엇 | 층 | 새 설정 | 문서 |
|---|---|---|---|---|---|
| B1 | 저장 시 정리 | 후행 공백·끝줄 정리 | 프런트 | 3 | [01](01-save-hygiene.md) |
| B2 | 자동 저장 | 지연·포커스 상실 시 저장 | 프런트 | 2 | [01](01-save-hygiene.md) |
| B3 | 미리보기 탭 | 훑을 때 탭이 안 쌓인다 | 프런트 | 1 | [02](02-preview-tabs.md) |
| B4 | 심볼·줄 이동 | ⇧⌘O · ⌃G | 프런트 | 0 | [03](03-goto.md) |
| B7 | 스티키 스크롤 | 상위 스코프 고정 | 프런트(CM6) | 2 | [04](04-sticky-scroll.md) |
| B6 | 문제 패널 | 프로젝트 진단 집계 | 프런트 + 얇은 백엔드 | 0 | [05](05-problems.md) |

건너뛰어도 나머지가 성립한다.

## 공용 결정

- **D1 — 설정은 프런트만 고친다.** `settings` 테이블은 범용 key/value 라 백엔드 변경이
  없다. 추가 자리는 `src/lib/settings.ts` 의 `KEYS` + `Settings` + `DEFAULTS`
  (역방향 `KEY_TO_FIELD` 는 파생) 와 `src/features/settings/CodeSettings.tsx` 뿐이다.
  기본값은 **전부 지금 동작 그대로** — 켜야 바뀐다. 이유는 `codeFormatOnSave` 가 기본
  꺼짐인 이유와 같다: 사용자가 만들지 않은 변경이 조용히 diff 를 덮으면 안 된다.
- **D2 — 새 커맨드는 브리지 절차를 지킨다.** `commands/` 에 핸들러 → `lib.rs` 의 `use` 와
  `collect_commands![]` **양쪽** → `cargo test` 로 `bindings.ts` 재생성. 프런트는
  `bindings.ts` 직접 호출 대신 기존 관례를 따른다(`lint:bindings` 게이트).
- **D3 — i18n 은 ko/en 동시.** 새 문자열은 `src/i18n/ko.ts` · `en.ts` 양쪽에 넣는다
  (`lint:i18n` 이 하드코딩 한국어를 막는다).
- **D4 — CSS 자리.** 이 라운드의 UI 는 전부 코드 화면 안에 산다 → `features/code/code.css`.
  전역(창 최상위)에서 뜨는 것은 없다. (2026-09-02 사고 — 창 어디서나 뜨는 모달 CSS 를
  lazy 청크에 두면 뼈대만 나온다. `scripts/check-critical-css.mjs` 참고.)
- **D5 — Phase 마다 닫는다.** `pnpm typecheck` · `pnpm test` · `pnpm lint` · `pnpm build`
  4게이트 exit 0 → 일지 1건(`journal_write`) → `plan_update`. 릴리스는 라운드 끝에 한 번
  (`docs/RELEASE.md` 의 5면).
- **D6 — 순수 로직은 모듈로 뗀다.** 이 라운드가 만드는 순수 함수는 전부 컴포넌트 밖에
  둔다(`codeTabs.ts`·`treeUtils.ts` 의 선례): `saveHygiene.ts` · `previewTabs`(codeTabs 확장)
  · `gotoModel.ts` · `stickyModel.ts` · `problemsModel.ts`. 로컬 히스토리는 계산이 백엔드에
  있으므로 같은 원칙을 Rust 쪽에서 지킨다(`oculpm/history.rs` 는 파일시스템 경계만 남기고
  레이아웃·보존 정책을 순수 함수로 뗀다).
  jsdom 이 레이아웃을 안 그리므로, 검증 가능한 부분을 최대한 순수 함수로 밀어낸다.
- **D7 — 에이전트 편집과 겨루지 않는다.** 자동 저장·저장 정리·로컬 히스토리 어느 것도
  **디스크를 먼저 읽어 덮어쓰지 않는다.** 전부 기존 낙관적 잠금(`code_write` 의
  `base_hash`)을 그대로 통과하고, 어긋나면 지금처럼 충돌 배너를 띄운다.

## 하지 않는 것 (이번 라운드 밖)

- **핫 엑싯(미저장 버퍼 디스크 백업)** — `codeBuffers.ts` 에 "영속하지 않는다: 재시작 후
  디스크와 다른 유령 버퍼가 더 위험하다" 는 결정이 이미 있다. 뒤집으려면 그 결정을 먼저
  다뤄야 한다. B2(자동 저장)가 같은 통증의 90%를 없앤다.
- **미니맵** — 분할 + svg 미리보기까지 겹치는 패인 폭에서 값보다 자리값이 크다.
- **피크 뷰(인라인 정의 팝업)** — 참조 패널이 이미 있고, CM6 에서 zone widget 을 새로
  만드는 비용이 크다. B4 로 이동 비용을 먼저 낮추고 재평가한다.
- **파일 중첩 / 압축 폴더** — 값은 있으나 트리 렌더·키보드 이동·경로 정합을 전부 건드려
  이 라운드의 어느 항목보다 크다. 다음 라운드 후보.

## 검증 게이트 (라운드 공통)

각 Phase 는 아래를 만족해야 닫힌다.

1. 4게이트 exit 0.
2. **순수 함수 테스트** — 그 Phase 가 만든 모델 함수의 경계 케이스.
3. **회귀 테스트** — 기존 저장/탭/충돌 경로가 그대로인지 (`code_screen.test.tsx`).
4. **육안 1회** — 설치본을 끄고 dev 로 한 바퀴 (설치본 도는 중 dev 빌드 금지 규율).
