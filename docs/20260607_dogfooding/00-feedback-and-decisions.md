## 1. 원본 피드백 (4영역)

### 사이드바
- 왼쪽 사이드바를 최소화하는 버튼 필요. 최소화 시 아예 안 보이다가, 커서가 사이드바 쪽으로 가면 알아서 튀어나오고, 버튼을 다시 누르면 보이게.

### 작업 일지
1. 코드 변화줄이 모두 `0+` 로 보이는 버그 → 작업 일지에서 어떤 파일이 변화됐는지 표시 삭제.
2. 변경된 파일 클릭 시 UI(모달)가 뜨며 변경 부분이 보임(좋음). 그러나 변화가 큰 파일은 **위가 잘림** (UI 버그).
3. 코드 줄이 길어지면 아래로 내려가(두 줄로 보여) 가독성이 떨어짐. **한 줄**로 보고 싶음.
4. AI 가 한 번의 작업에서 한 파일을 두 번 수정하면 두 번 잘 기록되는지 궁금.
5. 동일 이름 파일이 다른 경로에 있으면 구분이 안 됨 (예: `adelie/config.py` vs `adelie/commands/config.py` 둘 다 `config.py` 로 보임).
6. journal 파일의 자세한 텍스트(추가기능·동작흐름·검증·메모)를, 클릭 시 유저에게 잘 보이게 하면 "왜 이렇게 변했나"를 쉽게 알 수 있을 것.

### Planner
> 플래너는 AI 가 바이브 코딩하며 언젠가 완성될 체크리스트. 한 거대한 plan md 가 완성되면 유저는 또 다른 플랜을 세우거나 중간에 새 플랜을 요청할 수도 있음. 멀티버스처럼 planner 폴더 안에 다중 plan 이 생성/전환될 수 있어야 함.
1. 한 파일의 모든 플랜이 끝났으면 AI 가 임의로 더 수정하지 않게 명시 (다음 단계로 넘어가기 위해).
2. 다중 plan 을 사용자가 왔다 갔다 할 수 있게.

### 변경 diff
1. 파일 삭제 시 `Failed to read adelie/plan_mode.py: No such file or directory (os error 2)` — 버그. 삭제된 파일을 설명하는 모달이 떠야 함.
2. 프로젝트 내에서 잠시 존재하는 캐시 같은 파일(`**redacted/sensitive**:cadb26c2`)과 `!` 가 있는 임시파일까지 추적함 — 버그. 추적 안 하게.
3. 변경 파일을 그냥 나열하지 말고, 어떤 작업 일지 또는 어떤 plan 에서 수정된 파일인지 **묶음**으로.
4. 우측 상단에 **모두 검토 완료** 버튼.

## 4. 부록 — #4 조사 결과 (코드 변경 없음)

"한 작업에서 한 파일을 두 번 수정하면?" → `src-tauri/src/oculpm/entry_diffs.rs::capture_entry_diffs` 가 `git diff HEAD -- <path>` 를 캡처하므로, HEAD 이후의 **모든 변경(두 편집의 합본)**이 하나의 patch 로 기록된다. frontmatter `files_touched` 는 파일을 1회만 나열. → **누적 기록됨(정상)**. 단 caveat: 편집 도중 커밋이 끼면 커밋 이후 변경만 HEAD diff 에 남음(스냅샷 fallback 이 일부 보완).
