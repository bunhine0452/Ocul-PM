## TL;DR

1. **약 1.4만 줄이 즉시 삭제 가능하다.** `src/legacy/**` 11,827줄(빌드/테스트/린트에서 이미 제외) + 비-legacy 죽은 코드 ~1,800줄. 전체 프런트엔드의 **약 1/3**이 죽은 무게다. 유일한 걸림돌은 테스트 1개(`lite_w6_safety_net.test.ts`)가 `@/legacy/FileExplorer`의 순수 헬퍼 2개를 물고 있는 것뿐 — 이것만 이전하면 폴더 전체를 지울 수 있다.

2. **백엔드에 "고아 커맨드"가 약 30개 있다.** `bindings.ts`에는 생성돼 있으나 활성 UI 에서 호출하는 곳이 0인 `#[tauri::command]` 들이다. **그런데 이들의 절반은 쓰레기가 아니라 "UI 가 안 붙은 완성된 기능"이다** — `compare_layers`(정직성 감사), `set_journal_verified`(검토 루프), `generate_seed_goals`(그린필드 AI 목표), Project Overview 파이프라인(회고/인사이트)이 그 예. **삭제 vs 재활성화를 분류하는 것이 이 보고서의 핵심 산출물이다.**

3. **정리보다 더 시급한 정합성 버그 3가지가 있다** (→ `02-structural-debt.md`):
   - **플래너 이중화**: 파일 기반 `.oculpm/planner/*.md`(Planner 화면)와 레거시 SQLite goals/subtasks 가 공존하는데, **Today 의 "다음 할 일", AI 챗의 플래너 액션, 그린필드 시드 목표가 전부 죽은 SQLite sink 에 쓰고 있다.** 사용자는 Planner 화면에서 그 결과를 영원히 못 본다.
   - **redaction 미연결**: `redact_text`(시크릿 마스킹)는 구현·테스트까지 끝났지만 **플래너 읽기 경로에만** 연결돼 있다. 일지 본문·diff sidecar 는 무방비 — 이게 LLM 컨텍스트로 들어가고 git 으로 커밋된다. CLAUDE.md 의 "never put secrets in journals/diffs" 가 코드로 지켜지지 않는다.
   - **"자동 갱신" 약속 미실현**: 마스터플랜의 간판 문구("일하는 그 에이전트가 일지를 쓰며 대응 Plan 항목도 스스로 갱신")가 미구현. 플랜은 수동 "AI 갱신" 버튼이나 외부 에이전트의 수기 편집으로만 바뀐다.

4. **백엔드가 프런트보다 앞서 있다.** 위 고아 커맨드들이 증명하듯, 다음 기능 다수는 새 백엔드가 아니라 **이미 존재하는 능력에 UI 한 겹**만 얹으면 된다. 그래서 임팩트 대비 노력이 매우 높은 후보가 많다.

5. **권장 1순위 = "redaction 읽기/쓰기 경로 연결"** (effort S~M, impact high). 모든 공유/AI/회고 기능의 안전 전제이자, 그 자체로 잠재 보안 버그를 닫는다. 5개 분석 관점 중 4개가 이 항목을 전제로 지목했다.

## 분석 방법

이 보고서는 단일 패스 읽기가 아니라 **다중 에이전트 오케스트레이션**(98개 서브에이전트, 4단계)으로 작성됐다:

1. **Audit (9개 영역 병렬 정독)** — legacy 폴더 / 활성 프런트 / 프런트 코어 / Rust 마이그레이션 / Rust 커맨드 / Rust 코어 / npm 의존성 / cargo·에셋 / 테스트·설정.
2. **Verify (적대적 검증)** — 각 "죽은 코드" 주장을 회의적 입장의 별도 에이전트가 `grep`/`rg`로 **실제 참조를 찾으려 시도**해 반증. `isDead`/`safeToDelete` 판정은 이 검증을 통과한 것만.
3. **Map (11개 제품 도메인 역량 지도)** — Today / 작업 일지 / Planner / Diff / 코드 맵 / 의미 검색 / AI 패널 / 터미널 / 문서 뷰어 / 온보딩·설정 / 플랫폼·인프라. 각 도메인의 현재 능력 · 구체적 격차 · `docs/` 설계 대비 미구현 항목.
4. **Features (5개 관점에서 근거 기반 제안)** — AI-네이티브 / 파워유저 / 협업·공유 / 도입·통합 / 신뢰성·규모.

검증으로 걸러진 대표적 오탐: `git::read_changelog`(마크다운 `CHANGELOG.md` 리더 — SQLite changelog 와 무관, 살아있음), `bindings.ts`(자동 생성), `dist/`(gitignore 됨, 정상 빌드 산출물). 이런 항목들은 정리 대상에서 제외했다.

## 권장 로드맵 (정리 + 기능 통합)

정리와 기능을 따로 보지 말 것 — **상당수 "죽은 코드"가 미완성 기능이라, 정리하면서 동시에 기능을 살리는 게 맞다.**

### Phase 0 — 안전 전제 (지금)
- **R1. redaction 을 일지·diff 쓰기/읽기 경로에 연결** (effort S~M). → 02·03 문서. 이후 모든 AI/공유 기능의 전제.
- **C1. `src/legacy/**` 삭제 준비** — `flattenVisibleNodes`/`nextFocusedPath` 를 `src/features/code/fileTreeNav.ts` 로 이전 + 테스트 재배선. → 01 문서.

### Phase 1 — 정리 + 구조 부채 (다음 1~2 릴리스)
- **C2. `src/legacy/**` + 비-legacy 죽은 코드 일괄 삭제** (~13.6k줄). npm `@fontsource-variable/geist`·`recharts`·`date-fns`, cargo `gray_matter`·`fs2` 제거.
- **C3. 고아 백엔드 커맨드 분류 적용** — "삭제" 군(~20개) 제거, "재활성화" 군은 기능 백로그로.
- **S1. 플래너 이중화 해소** — Today/AI챗/그린필드를 파일 기반 plan 으로 일원화, 레거시 SQLite goals 경로 폐기. → 02 문서.

### Phase 2 — 임팩트 기능 (분기)
- **F1. 자동 일지→플래너 화해** (on-journal-write reconciliation) — 간판 약속 실현. (transformative)
- **F2. 정직성 감사** — `compare_layers` 재활성화: 에이전트가 빠뜨린 변경 탐지 + 일지 자동 초안. (high)
- **F3. 백엔드 기반 저널 쿼리 + 무한 타임라인** — 14일 인메모리 한계 제거. (high)
- **F4. 회고/인사이트 생성** — overview 파이프라인 재활용 + 코드그래프 hub 교차. (high)

### Phase 3 — 큰 베팅 (선택)
- **F5. Git 히스토리 백필** — 기존 레포의 콜드스타트 절벽 제거(도입 전환점). (transformative)
- **F6. 스탠드업/PR 본문 생성 + 공유 가능한 일지 내보내기** — 로컬 기록을 팀 산출물로. (high)
- **F7. 심볼 단위 코드맵 + 증분 그래프 재구축** — 규모 대응. (medium)

각 항목의 상세 근거·파일·노력 추정은 `01`·`02`·`03` 문서 참조.
