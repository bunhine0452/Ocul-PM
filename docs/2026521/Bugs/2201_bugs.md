[x] 채팅 stream 이 안되는 버그 (새 대화 생성 시 UI 업데이트 누락)

- 발생 원인: 새로운 대화(conversation)를 시작할 때, `send` 함수 내부에서 `messages` 상태를 초기 질문과 빈 응답(placeholder)으로 로컬에 업데이트한 뒤 곧바로 `setCurrentConvId`를 호출합니다. 이로 인해 `currentConvId`의 변경을 감지하는 데이터 불러오기 `useEffect`가 실행되며, 아직 데이터베이스에 스트리밍 중인 응답이 저장되지 않은 상태에서 데이터베이스 내역(사용자 질문만 존재)을 가져와 `messages`를 덮어씁니다. 결과적으로 빈 응답(placeholder) 객체가 상태에서 삭제되므로 채널로 수신된 텍스트 델타(delta)를 덧붙일 대상을 찾지 못해 스트리밍 UI가 갱신되지 않고, 새로고침 시에만 DB에 최종 저장된 메시지가 나타났습니다.
- 해결 방법: `currentConvId`를 감지해 DB에서 메시지를 불러오는 `useEffect` 상단에 `if (pending) return;` 구문을 추가했습니다. 이를 통해 답변 생성 스트리밍이 진행 중일 때는 데이터베이스에서 불완전한 상태를 불러와 로컬 스트리밍 상태를 덮어쓰지 않도록 수정했습니다.

[x] 상단에 모델 제공자 변경시 모델도 자동으로 변경되어야함

- 발생 원인: `ModelSelector` 컴포넌트에서 제공자(Provider) 드롭다운을 클릭해 제공자를 변경할 때, `onProviderChange` 이벤트만 호출하고 선택된 제공자에 호환되는 모델로 업데이트하는 로직이 누락되어 있었습니다.
- 해결 방법: 제공자 변경 `onClick` 핸들러 내에서 `onProviderChange(p)`를 호출하는 동시에 `onModelChange(KNOWN_MODELS[p][0])`를 호출하도록 추가하여, 제공자가 변경될 때 해당 제공자의 기본 모델(첫 번째 배열 요소)로 자동 변경되도록 수정했습니다.
